# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview
Flask web app that logs a user in through Zerodha Kite Connect v3 (`kiteconnect` Python SDK), then shows a "Login Successful" page with profile info and a bulk backfill of historical candles for all NSE equity stocks (https://kite.trade/docs/connect/v3/historical/).

## Commands
- Install: `pip install -r requirements.txt`
- Run: `python app.py`, which serves http://127.0.0.1:5000 (debug off, so code edits don't restart the server and kill a running download)
- No test suite or linter is configured. To check routes quickly, use Flask's test client: `from app import app; app.test_client().get('/')`. Importing `app` creates or updates `.env` (see below).

## Architecture
- `app.py` holds all routes. Templates extend `templates/base.html`, which contains the shared CSS and loads React 18 (UMD, cdnjs) and `htm` (unpkg) from CDNs: no Node, no build step, no static files. Each page passes its data to React as JSON in `<script id="boot" type="application/json">{{ ...|tojson }}</script>` and renders into `#root` with htm tagged templates. The React script bodies are wrapped in `{% raw %}...{% endraw %}` because htm's `${{...}}` style objects clash with Jinja; use `className`/camelCase SVG attributes, not `class`/`stroke-width`. The UI needs internet access to load React and fonts.
- Login flow: `GET /` shows a form for the API key and secret. `POST /login` saves them to `.env`, then redirects to `KiteConnect.login_url()`. Zerodha redirects back to `GET /callback?request_token=...&status=success`, and `generate_session()` exchanges the token for an `access_token`. That token and the user details go into the Flask session. Then `/success` shows the profile and the bulk-download form, and `/logout` calls `invalidate_access_token()` and clears the session.
- The Redirect URL registered in the Kite developer console must be exactly `http://127.0.0.1:5000/callback`.
- Config lives in `.env`, which is gitignored. It is read and written by the hand-written `load_env()` / `save_env()` in `app.py`. `python-dotenv` is deliberately not used. Credentials are read again on every request through `credentials()`, so changing them needs no restart. Keys: `KITE_API_KEY`, `KITE_API_SECRET`, `KITE_ACCESS_TOKEN` (written by `/callback`, removed by `/logout`), `KITE_DATA_DIR` (the last save folder used for bulk download), and `FLASK_SECRET_KEY` (generated automatically on first import; keeps sessions valid across restarts).
- On the login form, a blank secret with an unchanged API key keeps the saved secret.
- The access token is kept in the Flask session cookie and in `.env`. The bulk job reads it from `.env`. Never print or log it or the secret. Kite tokens expire daily, so the user must log in again each day.
- Historical data needs the paid Kite Connect Historical add-on. Without it, the API error is shown on the success page.
- Bulk download (`/download/start`, `/download/stop`, `/download/status`): the form takes a save folder (must be an absolute path; it is created and write-tested before the job starts; defaults to `<project>/data`), a start date, an end date (max 365 days, end date not in the future), `minute` or `day` (EOD), a speed in req/s (default 2.5), a file format (`csv` default, or `parquet`), and an "Include ETFs" option. ETFs are detected by a name/symbol heuristic in `is_etf()`. A single background thread (`bulk_download`) fetches NSE equity: segment `NSE`, type `EQ`, no liquidity filter, then `is_equity()`. `series_suffix()` treats the text after the last `-` as an NSE series only when it is exactly 2 characters, so `BAJAJ-AUTO` and `NAM-INDIA` count as normal equity. Kept: no suffix, plus `-BE`/`-BZ` when "Include trade-to-trade" is ticked (the default). Everything else is excluded: bonds, NCDs, G-secs, T-bills, SGBs and SME (`-N*`, `-Y*`, `-Z*`, `-GB`, `-GS`, `-SG`, `-TB`, `-RR`, `-SM`, `-ST`, ...). The selected count and breakdown are printed and shown on the page (`JOB["filter_info"]`); the expected count is about 2,000 to 2,300.
  - Requests: the range is split by `make_chunks()` into Kite's per-request limit (`INTERVALS`: 60 days for minute). `RateLimiter` spaces request starts by 1/rate, halves the rate on a 429, and recovers after 20 successes. `fetch_chunk()` retries 429s and network errors with backoff `min(2**n, 60)` s, up to 10 tries, then marks the chunk FAILED. A TokenException or 403 stops the job (`AuthStop`).
  - Progress: `<folder>/progress.sqlite`, table `chunks`, keyed by `(run, symbol, chunk_from)` with `run = run_key()` = `"<interval>:<from>:<to>"`, plus `":csv"` for CSV runs, so switching format re-downloads instead of skipping. Status is PENDING, DONE or FAILED, committed after every chunk. An empty response counts as DONE. Start / Resume with the same dates skips DONE chunks. After pass 1, FAILED chunks are re-looped until none remain or a pass fixes nothing.
  - Output: `save_candles()` merges into `<folder>/<interval>/<SYMBOL>/<year>.<csv|parquet>`, splitting by year, deduplicating on `date` (tz-naive IST) and sorting, with an atomic temp-file replace. Symbols that are reserved names on Windows get a `_` suffix. Errors go to `<folder>/errors.log`. Everything for a run lives in its folder, so resuming needs the same folder. The default `data/` is gitignored.
  - `POST /browse-folder` opens a native folder dialog by running tkinter in a subprocess (`BROWSE_SCRIPT`), which keeps Tk off Flask threads. It works because the server and the browser are on the same machine. The page shows progress as chunks done / total and polls `/download/status` every 2 s. The dashboard (`success.html`) has a planner card (segmented interval, date presets, speed slider, toggles, folder) whose JS mirrors the server checks and `make_chunks()` for a live estimate and window ruler, and a live card (progress ring, throughput sparkline computed from `requests` deltas between polls, stat tiles, a scrollable list of every stock completed in the current job: `JOB["completed"]`, sent incrementally by `/download/status?since=<n>` as `completed_new` and reset per job via `job_no`). Start / Stop / Browse use `fetch`; start reads `?error=` from the redirect URL and shows toasts. The start button reads "Resume download" when the form matches a partly done run in `JOB`.
  - Job state lives in memory (`JOB`), so a restart, including the debug reloader when you edit a `.py` file, stops the job. Resume is safe.
