# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview
Flask web app that logs a user in through Zerodha Kite Connect v3 (`kiteconnect` Python SDK), then shows a dashboard for bulk-downloading historical candles for all NSE equity stocks and selected NSE indices (NIFTY 50 spot etc.) (https://kite.trade/docs/connect/v3/historical/) and watching the job's progress live. It also runs a daily F&O job for NIFTY (Kite NFO) and SENSEX (Kite BFO) (1-minute candles with OI for every live future and option, saved in the Accelpix layout) from a dashboard card or `nifty_daily.py`, and checks each saved day against the exchange's F&O bhavcopy, NSE's for NIFTY and BSE's for SENSEX (dashboard "Bhavcopy check" card or `nifty_bhav.py`). `nse_reference.py` collects NSE delisting, suspension and merger reference data since 2015 (no broker login). The UI calls itself "Kite Backfill". Everything runs locally on one machine.

## Architecture
- Code layout:
  - `app.py` only creates the Flask app, sets the secret key and registers the three blueprints.
  - `config.py` holds paths and the `.env` helpers (`load_env`, `save_env`, `credentials`, `dhan_credentials`, `secret_key`, `data_dir`, `weekly_expiry_weekday`, `keep_zero_volume`, `trim_to_bhav`) and the defaults `KEEP_ZERO_VOLUME` and `TRIM_TO_BHAV`.
  - `auth.py` is the `auth` blueprint: `/`, `/login`, `/callback`, `/logout`.
  - `dhan.py` is the `dhan` blueprint: `/dhan`, `/dhan/login`, `/dhan/logout`, `/dhan/dashboard`, `/dhan/fno-window`, `/dhan/fno-start` (Dhan sign-in and the Dhan F&O page; see below).
  - `dashboard.py` is the `dashboard` blueprint: `/success`, `/download/*` (incl. `/download/fno-start` and `/download/fno-window`), `/fno/*` (bhavcopy check), `/browse-folder`.
  - `nifty_daily.py` (repo root) is the CLI for the daily F&O job.
  - `nifty_bhav.py` (repo root) is the CLI for the NSE bhavcopy check (`backfill/bhav.py`).
  - `fno_store.py` (repo root) is the CLI for `backfill/fno_store.py` (move-raw, split-stores), `backfill/fno_derive.py` (derive-without, compare-variants) and `backfill/fno_publish.py` (publish); `backfill/fno_backtest.py` reads the store.
  - `nse_reference.py` (repo root) is the CLI for the NSE delisting / suspension / merger reference (`backfill/nse_ref/`).
  - The `backfill/` package is the download engine and has no Flask imports. It contains `job.py` (`JOB`, `JOB_LOCK`, `STOP`), `fetch.py` (`INTERVALS`, `make_chunks`, `RateLimiter`, `fetch_chunk`, the stop exceptions), `instruments.py` (equity/ETF filter, `INDEX_CHOICES`, `is_index`), `storage.py` (`run_key`, `job_run_key`, `check_folder`, candle files, `progress.sqlite`, `errors.log`), `runner.py` (`bulk_download`), `fno.py` (daily F&O job), `dhan_api.py` (`DhanClient`, a Kite-shaped DhanHQ v2 client, and `fetch_profile`), `bhav.py` (NSE bhavcopy check), `bhav_export.py` (downloads of the check), `fno_days.py` (the day-count marker and `days_index.csv`), `fno_rename.py` (`--rename-folders`, `--update-day-count`), `fno_loader.py` (reads saved raw F&O days back), `fno_store.py` (move-raw, split-stores), `fno_derive.py` (the without-zero-volume copy of a with day), `fno_publish.py` (raw -> backtest store) and `fno_backtest.py` (reads the backtest store), plus the `nse_ref/` subpackage (NSE reference data); see below.
  - Templates use blueprint endpoint names in `url_for`, e.g. `auth.login` and `dashboard.download_start`.
- Templates extend `templates/base.html`, which contains the shared CSS (dark theme, Manrope font) and loads React 18 (UMD, cdnjs) and `htm` (unpkg) from CDNs: no Node, no build step, no static files. Each page passes its data to React as JSON in `<script id="boot" type="application/json">{{ ...|tojson }}</script>` and renders into `#root` with htm tagged templates. The React script bodies are wrapped in `{% raw %}...{% endraw %}` because htm's `${{...}}` style objects clash with Jinja; use `className`/camelCase SVG attributes, not `class`/`stroke-width`. `base.html` also defines shared `Toasts`, `useToasts`, `Logo` and `BrokerTabs` (the Zerodha / Dhan tab links at the top of both sign-in cards, `/` and `/dhan`). The UI needs internet access to load React and fonts.
- Login flow: `GET /` shows the sign-in page (`login.html`) for the API key and secret. `POST /login` saves them to `.env`, then redirects to `KiteConnect.login_url()`. Zerodha redirects back to `GET /callback?request_token=...&status=success`, and `generate_session()` exchanges the token for an `access_token`. That token and the user details go into the Flask session. Then `/success` shows the dashboard (`success.html`), and `/logout` calls `invalidate_access_token()` and clears the session. Errors come back as `?error=` and are shown on the page (inline on sign-in, as a toast on the dashboard).
- The Redirect URL registered in the Kite developer console must be exactly `http://127.0.0.1:5000/callback`.
- Dhan sign-in (`dhan.py`, `dhan_login.html`): the user pastes a Client ID and an access token generated on web.dhan.co (no API key / redirect flow). `POST /dhan/login` (blank token with unchanged Client ID re-checks the saved one) calls `dhan_api.fetch_profile()` (`GET https://api.dhan.co/v2/profile`, header `access-token`); the returned `dhanClientId` must equal the entered Client ID. It saves `DHAN_CLIENT_ID`, `DHAN_ACCESS_TOKEN` and `DHAN_TOKEN_EXPIRY` (`parse_validity()` turns Dhan's `tokenValidity` "DD/MM/YYYY HH:MM", IST, into ISO); `session["dhan_user"]` holds client id and `dataPlan` (not the token). Then `/dhan/dashboard?dhan=1`. `/dhan/logout` removes the token keys locally only. `dhan.status(env)` (connected = token present and expiry, IST, in the future) feeds the Dhan pages and the Kite dashboard's account menu (`boot.dhan`, with "Open Dhan F&O"); the Kite dashboard passes its own `load_env()` so tests' stubs cover it. Errors never include the token. Kite and Dhan sessions are independent; `/browse-folder` accepts either.
- Dhan F&O page (`/dhan/dashboard`, needs a valid Dhan token): renders `success.html` with `mode="dhan"` and `broker` (`name`, `maxSpeed` 5, `defaultSpeed` 4, `urls.fnoWindow`/`fno`/`page`); in that mode `App` shows `FnoCard` + `Live` + `Feed` + the banners and `BhavCard` (no Planner), a `DhanMenu` plus a visible Log out button (`.nav-actions`, `/dhan/logout`), and `FnoCard` shows the same rows and buttons as on Kite (Re-check no-trade included; terminal hints add `--source dhan`). Every bhavcopy fetch sends `Q` (`underlying` plus `source: "dhan"` on the Dhan page), and `brand()` shows Kite wording from the check (lines, statuses, headers) as Dhan there. Kite mode passes `broker` with the Kite URLs and max 3, so it renders as before. The F&O card's texts are the same in both modes (broker name from `B.name`); the brokers differ only in Dhan's speed limit, data-plan check and folder (the trim to the bhavcopy is the same setting on both). `dhan.py` passes `weekly_expiry_weekday(underlying)` like the Kite routes. `/dhan/fno-window` (live expiries from Dhan's list, cached per IST day in `dhan.LIVE`, history from the Dhan folder) and `POST /dhan/fno-start` (`date`, `date_from`+`date_to`, `missing=1`, or `refetch=1` with the Kite route's refusals, `speed` 0 < s <= 5, `folder`, `keep_zero`, `trim_bhav`; checks the token and refuses unless the profile's data plan is Active, then window/too_early, lock, `job_begin`) run `fno.run_daily` / `run_missing` / `refetch_no_trade` in a thread with `kite=DhanClient(token)` and `source="dhan"`. The token rule (`dhan_api.token_connected`/`token_ok`) and the plan check (`data_plan_error`) live in `backfill/dhan_api.py` so the CLI shares them without Flask. Stop and status reuse `/download/stop` and `/download/status`.
- `backfill/dhan_api.DhanClient` implements what the F&O job uses from KiteConnect: `profile()`, `instruments(exchange)` (Kite's NFO/BFO mapped by `SEGMENT_OF` to `GET https://api.dhan.co/v2/instrument/NSE_FNO` or `/BSE_FNO`; each row's `exchange` is the segment, and `historical_data` sends the segment remembered per security id, also learned by `learn()` from a saved list; FUTIDX/OPTIDX rows as Kite-style dicts: `name`=UNDERLYING_SYMBOL, FUT/CE/PE from OPTION_TYPE, `expiry` from SM_EXPIRY_DATE, `strike`, `tradingsymbol`=`SYMBOL_NAME#SECURITY_ID` (Dhan's SYMBOL_NAME is the same for every expiry of a month, e.g. `NIFTY-Oct2026-25000-CE` for 13, 19 and 27 Oct; keyed by it alone, weeklies were written into the monthly file on 2026-10-07), `instrument_token`=SECURITY_ID; missing columns raise a clear error) `spot_token(underlying)` (`SPOT_IDS` NIFTY 13, SENSEX 51 on IDX_I, instrument INDEX; for the holiday check) and `historical_data()` (`POST https://api.dhan.co/v2/charts/intraday`, `interval` "1", `oi`, IST "YYYY-MM-DD HH:MM:SS" bounds; column arrays turned into candle dicts with IST datetimes). Errors are raised as kiteconnect exceptions so `fetch_chunk` treats them like Kite's: 401/DH-901 TokenException, DH-902 PermissionException (both stop the job), 429/DH-904 code 429 (rate halves), 5xx/DH-908 NetworkException (retry), DH-907/"no data" -> no candles, other 4xx InputException (contract FAILED).
- "Download only contracts in the bhavcopy" (`trim_to_bhav`, Kite and Dhan alike): `run_daily(trim_to_bhav=None)` means the setting (`fno.trim_default()` -> `config.trim_to_bhav()`: `.env` `TRIM_TO_BHAV` ON/OFF, else `config.TRIM_TO_BHAV` = True); `run_missing` resolves it once and passes it to every day, `refetch_no_trade` passes it on, `redownload_contract` never trims. The routes read `trim_bhav=1|0` (absent: the setting; dashboard `read_trim()`), the CLI `--trim-to-bhav`/`--no-trim-to-bhav`, and `job_fields(trim_to_bhav=)` sets `JOB["trim_to_bhav"]` (live card "Contracts: Bhavcopy only (ON) / Full list (OFF)"). When ON, run_daily calls `trim_contracts()` -> `(contracts, "ON"|"FALLBACK", reason)`: `bhav.listed_names()` gives our names of every contract of the underlying in the day's bhavcopy (saved `<day>/bhavcopy/nifty_bhav.csv`, else `fetch_bhav(budget=bhav.TRIM_BUDGET)` = 30 s for home page, tries and waits together, `BhavTimeout` after that; the download is saved like `run_bhav` does) and only those contracts are kept, traded or not (`keep_listed()`, shared with `rewrite_summary`); without it (404, any error, "bhavcopy fetch timed out") the full list is used, never a refusal. run.log gets `Contracts: trimmed to bhavcopy (kept N of M)`, `Contracts: full list (trim OFF)` or `Contracts: full list (bhavcopy not available: <reason>)`; on FALLBACK also `fallback_note()` = "Bhavcopy not available (<reason>): full contract list used", which also goes into the job message during and at the end of the run (the CLI prints it through `log`). summary.csv's last column `Trim_to_bhav` (ON / OFF / FALLBACK, blank for older days; `saved_trim()`) holds the last run's result and is kept by `rewrite_summary`, which, when it is ON, trims the saved dump the same way from the saved bhavcopy (no network), so `Listed_*` count the requested contracts on Kite and Dhan alike. Nothing is ever deleted: a full-list day re-run with ON keeps its extra files (EXTRA in the check). `fno_days` puts `Trim_to_bhav` in `days_index.csv` and the marker; never in the folder name. `fno.py` takes `source` ("kite" default, "dhan") in `fno_root`/`fno_folder` (`FOLDERS`: `<UNDERLYING>_FnO_1min` vs `<UNDERLYING>_FnO_1min_Dhan`), `read_expiries`, `record_expiries`, `load_window`, `holidays_logged`, `missing_dates`, `acquire_lock`, `run_key` (Dhan: `fno-dhan:NIFTY:NSE_FNO:<date>`), `exchange_of`, `job_fields` (sets `JOB["source"]`, reset per job via `COUNTERS`), `run_daily` and `run_missing` (which also accept a ready `kite=`/`user=`). The default keeps every Kite folder, key and message unchanged. `bhav.py` (`bhav_dir`, `read_check`, `unchecked_days`, `run_bhav`, `list_days`, `compare_rows`, `diff_rows`), `bhav_export.py` (every reader and `export`; `relabel()` renames `Kite*`/`KITE` to Dhan in Dhan output and file names get `_dhan`) and `fno.redownload_contract` (`kite=`, `source=`; `DhanClient.learn()` reads the instrument type from the saved `instruments_NSE_FNO.csv`) take the same `source`. The bhavcopy routes read `?source=` (`fno_source()`; `signed_in(source)`: Kite session, or a valid Dhan token) and pass it on, including to `locked_fno` and `refresh_live_summary`. The comparison files inside a day keep their `Kite_*` column names for both sources. `refetch_no_trade`, `inspect_contracts` (`kite=`, `source=`), the CLIs (`--source dhan`) and `fno_loader` (`source=`) work on both. `tests/test_dhan_bhav.py` covers the Dhan check, exports, routes and re-download.
- Config lives in `.env`, which is gitignored. It is read and written by the hand-written `load_env()` / `save_env()` in `config.py`. `python-dotenv` is deliberately not used. Credentials are read again on every request through `credentials()`, so changing them needs no restart. Keys: `KITE_API_KEY`, `KITE_API_SECRET`, `KITE_ACCESS_TOKEN` (written by `/callback`, removed by `/logout`), `KITE_DATA_DIR` (the last save folder used for bulk download), and `FLASK_SECRET_KEY` (generated automatically on first import; keeps sessions valid across restarts). Optional `WEEKLY_EXPIRY_WEEKDAY` / `WEEKLY_EXPIRY_WEEKDAY_<UNDERLYING>` (MON..SUN; NIFTY TUE, SENSEX THU by default) are used only for the F&O date-window fallback, and optional `KEEP_ZERO_VOLUME` (ON/OFF) overrides `config.KEEP_ZERO_VOLUME` (False; the user switches the default there), and optional `TRIM_TO_BHAV` (ON/OFF) overrides `config.TRIM_TO_BHAV` (True), and optional `DERIVE_WITHOUT_ZERO_VOLUME` (ON/OFF) overrides `config.DERIVE_WITHOUT_ZERO_VOLUME` (True; `config.derive_without()`, all three through `on_off_setting()`). `KITE_DATA_DIR` is also the starting folder of the F&O card and the CLIs' default `--folder`, unless the optional `FNO_RAW_KITE` / `FNO_RAW_DHAN` are set (`config.fno_raw_dir(source, variant=None, env=None)`; with them set they are the base of the two zero-volume stores, see F&O backtest store; boot `fno.folder` on the Kite page, the Dhan page's form folder unless the last job was a Dhan F&O job; `nifty_daily.default_folder(source)`, also per source for `--rename-folders`/`--update-day-count --source all`; `nifty_bhav.py`). With the key set, an F&O start no longer writes `KITE_DATA_DIR`. Optional `FNO_BACKTEST_DIR` (`config.fno_backtest_dir()`) is the backtest store (see below). `.env.example` lists the keys with blank values.
- On the login form, a blank secret with an unchanged API key keeps the saved secret.
- The access token is kept in the Flask session cookie and in `.env`. The bulk job reads it from `.env`. Never print or log it or the secret. Kite tokens expire daily, so the user must log in again each day.
- Historical data is included in the paid Kite Connect plan (Rs 500/month). API errors (e.g. an expired session) stop the job or fail chunks; they appear in the live card's status message and in `<folder>/errors.log`.
- Bulk download (`/download/start`, `/download/stop`, `/download/status`): the form takes a "Stocks" checkbox list (`equity` = NSE equity stocks, plus `indices` = any of `INDEX_CHOICES`: NIFTY 50, NIFTY BANK, NIFTY FIN SERVICE, NIFTY MID SELECT, INDIA VIX; at least one required), a save folder (must be an absolute path; it is created and write-tested before the job starts; defaults to `<project>/data`), a start date, an end date (end date not in the future; max `MAX_RANGE_DAYS` = 365 days when equity is ticked, max `MAX_INDEX_RANGE_DAYS` = 20 years for indices only; the UI's "Since 2015" preset is enabled only without equity), `minute` or `day` (EOD), a speed in req/s (default 2.5; server accepts 0 < s <= 3, the UI slider is 0.5 to 3), a file format (`FILE_FORMATS`: `csv` default, or `parquet`), and "Include ETFs" / "Include trade-to-trade" options (shown only when equity is ticked). ETFs are detected by a name/symbol heuristic in `is_etf()`. A single background thread (`bulk_download`) runs the selected parts one after another in one job: indices first (segment `INDICES`, matched by tradingsymbol, in `INDEX_CHOICES` order; NIFTY 50 is token 256265), then equity. `JOB["part"]` holds the current part text ("Indices: NIFTY 50", "Equity: 1,240 / 2,942 stocks"), and the stock/chunk counters cover all parts. Equity is segment `NSE`, type `EQ`, no liquidity filter, then `is_equity()`. `series_suffix()` treats the text after the last `-` as an NSE series only when it is exactly 2 characters, so `BAJAJ-AUTO` and `NAM-INDIA` count as normal equity. Kept: no suffix, plus `-BE`/`-BZ` when "Include trade-to-trade" is ticked (off by default). Everything else is excluded: bonds, NCDs, G-secs, T-bills, SGBs and SME (`-N*`, `-Y*`, `-Z*`, `-GB`, `-GS`, `-SG`, `-TB`, `-RR`, `-SM`, `-ST`, ...). The selected count and breakdown are printed and shown on the page (`JOB["filter_info"]`); the expected count is about 2,000 to 2,300, and more than `MAX_STOCKS` (3,000) refuses to start.
  - Requests: the range is split by `make_chunks()` into Kite's per-request limit (`INTERVALS`: 60 days for minute, 2,000 for day). `RateLimiter` spaces request starts by 1/rate, halves the rate on a 429, and recovers after 20 successes. `fetch_chunk()` retries 429s and network errors with backoff `min(2**n, 60)` s, up to 10 tries, then marks the chunk FAILED. A TokenException or 403 stops the job (`AuthStop`).
  - Progress: `<folder>/progress.sqlite`, table `chunks`, keyed by `(run, symbol, chunk_from)` with `run = run_key()` = `"<interval>:<from>:<to>"`, plus `":csv"` for CSV runs, so switching format re-downloads instead of skipping, plus `":idx"` for the index part, so index and equity progress never mix (equity keys are unchanged from before). `JOB["run"]` is `job_run_key()`: the part keys joined with `" + "`, which the planner mirrors (together with the selection) to detect Resume. Status is PENDING, DONE or FAILED, committed after every chunk. An empty response counts as DONE (counted in `empty`); e.g. index 1-minute windows before ~2015-01-09. Start / Resume with the same selection, interval, dates, format and save folder skips DONE chunks. A second table, `runs` (`run` -> run folder name, start time), is described under Output. After pass 1, FAILED chunks are re-looped until none remain or a pass fixes nothing.
  - Output: each part of a job writes into its own run folder, `run_dir_name()` = `<Equity_stocks|Index_spot>_<1min|EOD>_<from>_to_<to>_started_<YYYY-MM-DD>_<HHMM>` under the save folder. `run_dir()` records it in the `runs` table of `progress.sqlite` (`run` -> `dir`) the first time a run key starts, and Resume reuses it, so a resumed run never splits across folders (runs started before this table existed get a new folder). `JOB["out_dirs"]` lists the folders for the live card, and the planner's hint mirrors the name. `save_candles(out_dir, ...)` merges into `<run folder>/<SYMBOL>/<year>.<csv|parquet>`, splitting by year, deduplicating on `date` (tz-naive IST) and sorting, with an atomic temp-file replace. `read_year()` / `write_year()` handle the two formats; CSV dates are written as `YYYY-MM-DD HH:MM:SS` for minute data and `YYYY-MM-DD` for daily. Columns: `date, open, high, low, close, volume, tradingsymbol, instrument_token`. Spaces in symbols become `_` in the folder name (`NIFTY 50` -> `NIFTY_50`) while the `tradingsymbol` column keeps the real name; reserved Windows names get a `_` suffix. `progress.sqlite` and `errors.log` live in the save folder itself (next to the run folders), so resuming needs the same save folder. Data from before run folders existed sits in `<folder>/<interval>/<SYMBOL>/` and is left alone. The default `data/` is gitignored.
  - `POST /browse-folder` opens a native folder dialog by running tkinter in a subprocess (`BROWSE_SCRIPT`), which keeps Tk off Flask threads. It works because the server and the browser are on the same machine.
  - Dashboard (`success.html`): a planner card (Stocks checkbox list with nested trade-to-trade / ETF switches, interval switch, date presets incl. "Since 2015", speed slider, folder with Browse, CSV / Parquet switch) whose JS mirrors the server checks and `make_chunks()` / `job_run_key()` for a live estimate and window ruler; a live card (progress ring, current part, run folders under "Saving to", throughput sparkline computed from `requests` deltas between polls, stat tiles, run details, Stop); and a scrollable list of every stock and index completed in the current job.   - `backfill/fno_publish.py` `publish(raw, out, underlyings, ...)`: **never writes raw** (it only takes each raw root's `.lock` via `acquire_lock` while reading; busy -> that root skipped, exit 1). Per day and source with summary.csv (else listed as incomplete): `minute/<src>/<YYYY>/<date>.parquet` in `MINUTE_SCHEMA` (`day_frame()`: `fno_loader.read_contract_csv` with `fill_oi`, `bhav.parse_name`, `zero_volume` = the contract's day volume is 0; sorted by contract, datetime; atomic via `write_atomic`). **Incremental:** `publish_manifest.json` holds per day and source the folder and `fingerprint()` (files, bytes, newest mtime of the whole day folder) plus what days.csv needs; a day is rebuilt only when new, changed or `--force`. EOD (`eod/<YYYY>.parquet`, `fno_loader.load_eod` + `EOD_KEYS`) comes from Kite's saved bhavcopy, else Dhan's (`eod_source` in the manifest; the year file is updated per changed day). `contracts.parquet` (`CONTRACT_COLUMNS`; lot from EOD, else the saved instrument lists) and `expiries.csv` (`EXPIRY_COLUMNS`; monthly = last expiry of its month) are rebuilt every run; `days.csv` (`DAYS_COLUMNS`, plus `raw_missing`) from the manifest. **best_source** (`best_source()` -> (source, reason) for days.csv's `best_source` / `best_reason`): rank `CHECK_RANK` OK > minor > unchecked > major (`check_label()` from `bhav.list_days`); the same label is broken by `check_counts()` of bhav_check.json (kept in the manifest entry as `counts`) in `TIE_COUNTS` order, fewer wins: `missing`, then `volume` (`red_volume_diffs`, else `volume_diffs`), then `total` (sum of `bhav.COUNT_NAMES`); only all equal or unknown -> `--prefer` (kite); blank without a source; sources whose raw folder is gone count only when no other is left. A published day whose raw folder is gone is kept and marked until `--prune`.
  - `backfill/fno_backtest.py` reads only the store: `load_fno_day` (`source` best/kite/dhan, `expiry`/`types`/`strikes`/`drop_zero_volume` as pyarrow `filters`, `columns`), `load_fno_range` -> (frame, skipped dates), `load_eod`, `load_days`, `load_contracts`, `load_expiries`; `root` defaults to `config.fno_backtest_dir()`. `fno_loader.py` stays the raw reader.
- NSE delisting / suspension / merger reference (`backfill/nse_ref/`, `nse_reference.py`; sources verified 2026-10-14 and described in `nse_ref/__init__.py`):
  - Output in `<folder>/NSE_CM_bhav/reference/`: `voluntary_delisting.csv` (both Excel lists of the "Delisting of Companies" page `/static/list/list-of-companies-proposed-to-be-delisted`: every delisting type since `--from`, sheets merged by symbol+date, plus the proposed list; the whole list also feeds `lookup` = `name_key(company)` -> symbol), `compulsory_delisting.csv` (`/static/list/orders-of-delisting` HTML table; symbol by name from the lookup, else from the order PDF, else a `difflib` close match flagged for review), `delisting_circulars.csv`, `mergers.csv`, `suspensions.csv`, the user's `manual_mergers.csv` (created once with the HDFC example, never overwritten) and `text_cache/` (pdfplumber results, keyed by file size and `TEXT_VERSION`). Every CSV is rebuilt from `raw/` on each run (no merging; corrections go in `manual_mergers.csv`), written atomically, LF, ISO dates, with `needs_review` (Y or "") and `review_note`; `common.review(row, notes, info)`: notes set the flag, info is only appended (e.g. "symbol looked up by company name").
  - Circulars: `api/circulars?fromDate=&toDate=` per year returns every department (uncapped); `circulars.pick()` keeps one row per circular number, delisting = Listing/Emerge with "delist" (skips Dissemination Board, offers/calendars, non-equity), suspension = any department with "suspen" minus revocations/cancellations, member(ship) suspensions, non-equity (`NON_EQUITY`: bonds, NCDs, units, funds...) and other non-stock subjects (futures, repo, preference shares, warrants, rights entitlements); `suspensions.not_a_stock()` also drops table rows by Series (`MF`, `N*`, `GB`, ...) or a redemption/conversion reason; skipped counts go to the summary. Tables come from pdfplumber `extract_tables()` on `dedupe_chars()` pages (old PDFs repeat bold characters); `table_rows()` maps headers (Symbol / Name / Series / ISIN / Reason) and handles spacer cells; `symbols_in_cell()` strips footnote marks (`*`, `#`), joins wrapped symbols, upper-cases and splits `"A" & "B"` into two rows (a bare `&` stays: `SB&TINTL`). Without a table: `companies_in_text()` (numbered lines under 'Name of the Company', or 'securities of A Limited, B Limited and C Limited will be'), else the subject (`'Delisting - SYMBOL'` too), else the first company in the text (flagged). `delisting_type`: withdrawal / on hold (SAT stay) / liquidation / ibc / compulsory / voluntary / other. Missing symbols come from the lookup (exact `name_key`, else a `difflib` close match, flagged); `run.collect` parses the circulars twice so symbols a circular states (`learn_symbols`, never guessed ones) fill other circulars naming the same company.
  - `suspensions.classify()` (first matching `REASONS` label; `WEAK` 'court / NCLT order' only if nothing else matches) decides merger vs other from the row's Reason cell, else the text after the `Sub:` line (`body()`), and only when neither names a reason from the subject; merger + liquidation/IBC is flagged. Merger circulars almost never carry the new company or the swap ratio (the corporate-actions API only says "Merger"), so those are filled from `manual_mergers.csv` (`MANUAL_COLUMNS`; `apply_manual` clears `needs_review` on matched rows, and its optional `scheme_type` (`SCHEME_TYPE_RX`) / `exit_expected` (Y/N) override the parsed values, invalid ones are ignored and keep the row flagged; `note` is not copied; a 4-column file still works; unmatched symbols are printed), else flagged "swap ratio not in NSE circular". `last_trading_date` = "closing hours of trading on DATE". `scheme_type` (`SCHEME_PARTS` joined with `+`, OTHER flagged) and `exit_expected` (merger: MERGER part; suspension: `EXIT_REASONS`, N when CANCELLED) are guesses from the circular. `status` (`STATUS` on the subject: CANCELLED "not to be carried out", CONTINUED "continuation of suspension", else SUSPENDED); `link_cancellations()` sets `cancels_circular` to the SUSPENDED row of the same company that the text cites (`cited()`), else the latest earlier one. Corrections (`CORRECTION_SUBJECT` on the subject, or `CORRECTION_RX` in the body; an NCLT "Corrigendum order" in the text is not one) read dates after `CORRECTED_LEAD`, and `merge_corrections()` folds them into the cited original row (`corrected_by`). Rows carry `_cites` / `_correction` / `_date` for those passes (not written). A circular without a table whose cited circulars are all `NON_EQUITY` by subject is skipped (`only_non_equity`; run.py passes the subject index). Skip regexes are word-bounded and `_` reads as a space (a bare `unit\w*` once dropped "United Bank of India"; `bonds_IDFC`).
  - Fetching (`fetch.py`): `NseClient` opens `HOME` first (403 ignored), `Throttle` keeps request starts `GAP` = 2 s apart, 401/403, a page instead of the expected kind (`looks_like`) or `TRIES` network errors switch the rest of the run to `BrowserFetcher` (Playwright headless Chromium, imported lazily in `launch_browser`; a failed launch is not retried). `Cache` (`raw/<sub>/<safe_name(url)>`, atomic `.part` writes) never downloads a file that exists, including one the user saved by hand; pages and the current year's list are saved as `<stem>_fetched_<IST date>` (once a day, the newest copy is used offline or after a failed download), past years' lists and documents once. 404s go to `not_found` (asked again next run, exit code unchanged), other failures to `failures` (printed with the target path, exit 1).
- NSE F&O bhavcopy check (`backfill/bhav.py`, `run_bhav`):
  - Per exchange (`SOURCES`, `bhav_url(run_date, underlying)`; `fetch_bhav(..., underlying=)`, which every caller passes by keyword): BSE (verified 2026-10-13) is `BSE_BHAV_URL` (`www.bseindia.com/download/Bhavcopy/Derivative/BhavCopy_BSE_FO_0_0_0_<YYYYMMDD>_F_0000.CSV`), a plain CSV (not a zip) with the same `BHAV_HEADER`, Src BSE, TckrSymb SENSEX (BANKEX rows filtered out), volume AND OI in shares (`SOURCES[...]["volume"]`: the volume unit defaults to 1 without traded futures; `load_eod` divides by the lot for `Volume_contracts`); no home-page warm-up, Referer bseindia; a day not published comes back as 200 with BSE's HTML page, which raises `BhavNotAvailable` like NSE's 404 (a body starting with `TradDt` is the file). Saved as `<underlying>_bhav.csv` (`sensex_bhav.csv`) next to the original file; exports of a SENSEX check end in `_sensex`.
  - NSE source (verified UDiFF format, 2026-10-09): `BHAV_URL` (`nsearchives.nseindia.com/content/fo/BhavCopy_NSE_FO_0_0_0_<YYYYMMDD>_F_0000.csv.zip`) returns 200 without cookies; the `www.nseindia.com` home page answers scripts with 403 and that is ignored (`fetch_bhav`, 3 tries, 404 -> `BhavNotAvailable`, which only appends to `<UNDERLYING>_FnO_1min/bhavcopy.log`). Header in `BHAV_HEADER`; ISO dates. Rows: `TckrSymb == underlying`, `FinInstrmTp` IDF/IDO, names via `fno.contract_name`.
  - Units: `TtlTradgVol` is in contracts, `OpnIntrst` in shares, so `detect_unit()` finds the volume and OI multipliers separately from the futures (snapped to 1 or the lot).
  - Output in `<day folder>/bhavcopy/`: the original zip, `nifty_bhav.csv`, `bhav_compare.csv` (`COMPARE_COLUMNS`) and `bhav_check.json` (status, counts, severity), plus `write_bhav_summary()`: `bhav_summary.csv` (`SUMMARY_FILE_COLUMNS`: an `ALL` row with Date, Status and units, then one row per expiry and FUT/OPT; no per-difference files are written any more (old days may still have them; nothing reads them)), and `write_days_summary()`: `checked_days_summary.csv` (`DAYS_SUMMARY_FILE`), this day's row only, in the columns of the "All days summary (CSV)" download (which still lists every checked day; every file in a day's bhavcopy folder holds that day only; other days' copies are not rewritten; broker from the folder name, Dhan columns relabelled; skipped while no day has summary.csv). `check_saved()` re-runs the comparison from the saved file without network access (after `run_bhav` saves a download, after a re-download, and for `nifty_bhav.py DATE --bhav-file`). The check takes the same lock as the Kite job.
  - Statuses from `compare()` (combined with `+`): OK / MISSING_IN_KITE / EXTRA_IN_KITE / BAD_NAME / ZERO_VOLUME_IN_KITE (file with total volume 0, bhavcopy volume > 0: counted in `zero_volume`, a volume difference not a missing contract; always amber, even with VOLUME_DIFF) / VOLUME_DIFF (>1% AND >5 lots: `VOLUME_TOL`, `VOLUME_MIN_LOTS`) / OI_DIFF (>3%, `OI_TOL`: Kite OI is an intraday snapshot) / PRICE_DIFF (`LastPric` vs the close of Kite's last bar of the day only, within max(0.5%, 2 ticks)). Kite labels candles by start time, so the 15:30 candle is post-close; `Kite_last_regular` (last bar with Time < `REGULAR_END` 15:30) is for reference only. `Last_bar` is the last bar's time, and `Note` = "trades after Kite's last bar" when the price differs and that bar is before `LATE_BAR` 15:40. Futures `ClsPric` is never compared.
  - Buckets (`bucket_namer()`): options use `fno.bucket_labels`; futures are Current month / Next month by expiry order; the rest are `FAR`. It works from the expiries in the bhavcopy plus `parse_name()` of the files on disk, so EXTRA rows absent from the bhavcopy also get Expiry/Type/Strike/Bucket. Counts add `liquid_missing`, `liquid_diffs`, `liquid_volume_diffs` and `far_problems`; `check_status()` appends `; liquid buckets: X missing, Y diffs`.
  - Severity (`severity()`, stored in `bhav_check.json`): `major` (red) only for MISSING_IN_KITE in any bucket or a VOLUME_DIFF over the limits whose Kite volume is > 0 (`missing` + `red_volume_diffs`); everything else is a known Kite limitation and `minor` (amber, "CHECK (minor)") in every bucket, liquid included: ZERO_VOLUME_IN_KITE, EXTRA_IN_KITE, OI_DIFF, PRICE_DIFF (with or without "trades after Kite's last bar"); "" when OK. Buckets (`liquid_*`, `far_problems`) are for display only. `day_severity()` re-derives it from the counts (checks before `red_volume_diffs` use `volume_diffs`: no zero-volume files existed then); checks without those counts map `liquid`->major and `far`->minor (`OLD_SEVERITY`), or count as major. Grouping and colour must never drop a difference: totals, statuses and exit codes keep every one.
  - `summary.csv` carries `BHAV_SUMMARY_COLUMNS` plus one `Futures` row per future expiry; `fno.summary_rows()` recomputes them from the saved `nifty_bhav.csv` on every Kite run (so a re-run keeps the check) and `fno.rewrite_summary()` rebuilds summary.csv from the saved instrument list after a check.
  - `diff_rows()` returns non-OK rows sorted by bhavcopy volume descending, with `Bhav_volume_shares`, `Live` and `Liquid`; for old compare files without Bucket (or with the old price columns) it compares again in memory.
  - Dashboard routes, all JSON and synchronous:
    - `GET /fno/bhav-status` returns `list_days()` (saved days newest first, `ok`/`diffs`/`pending` plus severity) and `banners()`: `check` (major days among the last 10, red), `minor` (amber) and `pending_old` (pending days before yesterday, yellow, with "Check all pending").
    - `GET /fno/bhav-diff` returns the day's non-OK rows from `diff_rows()`, with `Bhav_volume_shares` and `Live` = expiry >= today.
    - `POST /fno/bhav-check` takes `date` or `missing=1` and returns per-day results.
    - `POST /fno/redownload` runs `fno.redownload_contract()` for one live contract (lock, rate limit, Kite token, or with source=dhan the same checks as a Dhan download: `token_ok`, then `data_plan_error(profile())`; `keep_zero=1` keeps zero-volume candles), then `check_saved`.
    - `GET /fno/bhav-export?scope=days|view|all|xlsx[&date=&bucket=]` sends `bhav_export.export()` as an attachment: the all-days summary (`DAY_COLUMNS`, checked days only), the difference list for a bucket filter (`all`/`liquid`/a bucket name, in the panel's order), every contract of the day, or the Excel report (sheets `SHEETS`: Summary with the day row and per-expiry rows, frozen at A5; Not OK; All contracts; Settlement; header frozen, autofilter, fitted widths). Contract rows use `CONTRACT_COLUMNS` (the panel's "bhav / Kite" pairs split, plus `Bhav_volume_shares`). It reads `bhav.compare_rows()` (the saved bhav_compare.csv, re-compared in memory only for files without Bucket), bhav_check.json and summary.csv, writes nothing, and returns 404 when the day (or every day) has no check. Values stay raw (`fmt_num`, no thousands separators); Excel gets numbers as numbers and dates/times as text.
    - Writing routes refuse while a job runs or the lock is held (`locked_fno`). Read routes never create the folder.
  - UI: `BhavCard` sits in a full-width row (`.full-row`) under both columns, so its tables show every column. Day rows are tinted by severity (`day-ok` / `day-diffs` / `day-minor` / `day-pending`) with a Liquid buckets column; the Volume diffs cell adds "N zero-volume" when `counts.zero_volume` > 0. The diff panel has a bucket filter (view only; the count line shows "n of N"), and Re-download for live contracts. `DownloadMenu` (a "Download ▾" button with a small menu) fetches `/fno/bhav-export` and saves the blob under the Content-Disposition name, so a missing check gives a toast, not an error page: "All days summary (CSV)" next to the day table; "This view (CSV)" (current bucket filter), "All contracts for this day (CSV)" and "Full report (Excel)" above the diff panel.
  - The F&O card has a second switch, "Download only contracts in the bhavcopy" (`trimBhav` in `App`, starting from `boot.fno.trim_to_bhav` on every load, sent as `trim_bhav`; its "Contracts" details row follows it on both pages). The F&O card and the `BhavCard` share `fnoFolder` and `keepZero` (the "Keep contracts with candles but zero volume" switch, starting from `boot.fno.keep_zero_volume`), which live in `App` along with the bhav day list and the banners. The card's date picker (`DayRangePicker`, inline calendar limited to the window, amber dot = missing, green = saved) picks one day with one click or a range with a second click; `/dhan/fno-start` accepts the same range fields. For a range, "Check vs NSE bhavcopy" checks each saved day in it and Re-check no-trade is hidden. The F&O card shows "Re-check no-trade contracts for <date>" for a saved day (enabled only with the switch ON). For F&O jobs the live card shows "No candles, no file" (`empty`) and "Zero-volume candles" (`zero_kept` + `zero_skipped`, with "kept N / skipped N") tiles instead of "Time left" (the ETA shows by the ring), and "Zero-volume contracts: Kept (ON) / Skipped (OFF)" (`JOB["keep_zero"]`) in the run details.
