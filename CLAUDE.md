# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview
Flask web app that logs a user in through Zerodha Kite Connect v3 (`kiteconnect` Python SDK), then shows a dashboard for bulk-downloading historical candles for all NSE equity stocks (https://kite.trade/docs/connect/v3/historical/) and watching the job's progress live. The UI calls itself "Kite Backfill". Everything runs locally on one machine.

## Commands
- Install: `pip install -r requirements.txt` (flask, kiteconnect, pandas, pyarrow)
- Run: `python app.py`, which serves http://127.0.0.1:5000. Debug is off, so neither `.py` nor template edits are picked up until the server is restarted (templates are cached). Restarting stops a running download; Resume is safe.
- No test suite or linter is configured. To check routes quickly, use Flask's test client: `from app import app; c = app.test_client(); c.get('/')`. Importing `app` creates or updates `.env` (see below).
- Pages behind login can be rendered without Kite by faking the session: `with c.session_transaction() as s: s["access_token"] = "x"; s["user"] = {...}`. To preview the UI in a browser, run a scratch script that imports `app`, adds a route setting those session keys, and fills `JOB` with sample values, then serves on another port (e.g. 5001). Do not start a real download from it. For screenshots, also override `app.credentials` to return `("", "")` so the sign-in page doesn't show the saved key.

## Architecture
- `app.py` holds all routes. Templates extend `templates/base.html`, which contains the shared CSS (dark theme, Manrope font) and loads React 18 (UMD, cdnjs) and `htm` (unpkg) from CDNs: no Node, no build step, no static files. Each page passes its data to React as JSON in `<script id="boot" type="application/json">{{ ...|tojson }}</script>` and renders into `#root` with htm tagged templates. The React script bodies are wrapped in `{% raw %}...{% endraw %}` because htm's `${{...}}` style objects clash with Jinja; use `className`/camelCase SVG attributes, not `class`/`stroke-width`. `base.html` also defines shared `Toasts`, `useToasts` and `Logo`. The UI needs internet access to load React and fonts.
- Login flow: `GET /` shows the sign-in page (`login.html`) for the API key and secret. `POST /login` saves them to `.env`, then redirects to `KiteConnect.login_url()`. Zerodha redirects back to `GET /callback?request_token=...&status=success`, and `generate_session()` exchanges the token for an `access_token`. That token and the user details go into the Flask session. Then `/success` shows the dashboard (`success.html`), and `/logout` calls `invalidate_access_token()` and clears the session. Errors come back as `?error=` and are shown on the page (inline on sign-in, as a toast on the dashboard).
- The Redirect URL registered in the Kite developer console must be exactly `http://127.0.0.1:5000/callback`.
- Config lives in `.env`, which is gitignored. It is read and written by the hand-written `load_env()` / `save_env()` in `app.py`. `python-dotenv` is deliberately not used. Credentials are read again on every request through `credentials()`, so changing them needs no restart. Keys: `KITE_API_KEY`, `KITE_API_SECRET`, `KITE_ACCESS_TOKEN` (written by `/callback`, removed by `/logout`), `KITE_DATA_DIR` (the last save folder used for bulk download), and `FLASK_SECRET_KEY` (generated automatically on first import; keeps sessions valid across restarts). `.env.example` lists the keys with blank values.
- On the login form, a blank secret with an unchanged API key keeps the saved secret.
- The access token is kept in the Flask session cookie and in `.env`. The bulk job reads it from `.env`. Never print or log it or the secret. Kite tokens expire daily, so the user must log in again each day.
- Historical data needs the paid Kite Connect Historical add-on. Without it, every chunk fails or the job stops with the API error, which appears in the live card's status message and in `<folder>/errors.log`.
- Bulk download (`/download/start`, `/download/stop`, `/download/status`): the form takes a save folder (must be an absolute path; it is created and write-tested before the job starts; defaults to `<project>/data`), a start date, an end date (max 365 days, end date not in the future), `minute` or `day` (EOD), a speed in req/s (default 2.5; server accepts 0 < s <= 3, the UI slider is 0.5 to 3), a file format (`FILE_FORMATS`: `csv` default, or `parquet`), and "Include ETFs" / "Include trade-to-trade" options. ETFs are detected by a name/symbol heuristic in `is_etf()`. A single background thread (`bulk_download`) fetches NSE equity: segment `NSE`, type `EQ`, no liquidity filter, then `is_equity()`. `series_suffix()` treats the text after the last `-` as an NSE series only when it is exactly 2 characters, so `BAJAJ-AUTO` and `NAM-INDIA` count as normal equity. Kept: no suffix, plus `-BE`/`-BZ` when "Include trade-to-trade" is ticked (the default). Everything else is excluded: bonds, NCDs, G-secs, T-bills, SGBs and SME (`-N*`, `-Y*`, `-Z*`, `-GB`, `-GS`, `-SG`, `-TB`, `-RR`, `-SM`, `-ST`, ...). The selected count and breakdown are printed and shown on the page (`JOB["filter_info"]`); the expected count is about 2,000 to 2,300, and more than `MAX_STOCKS` (3,000) refuses to start.
  - Requests: the range is split by `make_chunks()` into Kite's per-request limit (`INTERVALS`: 60 days for minute). `RateLimiter` spaces request starts by 1/rate, halves the rate on a 429, and recovers after 20 successes. `fetch_chunk()` retries 429s and network errors with backoff `min(2**n, 60)` s, up to 10 tries, then marks the chunk FAILED. A TokenException or 403 stops the job (`AuthStop`).
  - Progress: `<folder>/progress.sqlite`, table `chunks`, keyed by `(run, symbol, chunk_from)` with `run = run_key()` = `"<interval>:<from>:<to>"`, plus `":csv"` for CSV runs, so switching format re-downloads instead of skipping. Status is PENDING, DONE or FAILED, committed after every chunk. An empty response counts as DONE. Start / Resume with the same dates, format and folder skips DONE chunks. After pass 1, FAILED chunks are re-looped until none remain or a pass fixes nothing.
  - Output: `save_candles()` merges into `<folder>/<interval>/<SYMBOL>/<year>.<csv|parquet>`, splitting by year, deduplicating on `date` (tz-naive IST) and sorting, with an atomic temp-file replace. `read_year()` / `write_year()` handle the two formats; CSV dates are written as `YYYY-MM-DD HH:MM:SS` for minute data and `YYYY-MM-DD` for daily. Columns: `date, open, high, low, close, volume, tradingsymbol, instrument_token`. Symbols that are reserved names on Windows get a `_` suffix. Errors go to `<folder>/errors.log`. Everything for a run lives in its folder, so resuming needs the same folder. The default `data/` is gitignored.
  - `POST /browse-folder` opens a native folder dialog by running tkinter in a subprocess (`BROWSE_SCRIPT`), which keeps Tk off Flask threads. It works because the server and the browser are on the same machine.
  - Dashboard (`success.html`): a planner card (interval switch, date presets, speed slider, trade-to-trade / ETF switches, folder with Browse, CSV / Parquet switch) whose JS mirrors the server checks and `make_chunks()` / `run_key()` for a live estimate and window ruler; a live card (progress ring, throughput sparkline computed from `requests` deltas between polls, stat tiles, run details, Stop); and a scrollable list of every stock completed in the current job. It polls `/download/status` every 2 s. `JOB["completed"]` is sent incrementally by `/download/status?since=<n>` as `completed_new` (plus `completed_count`) and reset per job via `job_no`. Start / Stop / Browse use `fetch`; start reads `?error=` from the redirect URL and shows toasts. The start button reads "Resume download" when the form matches a partly done run in `JOB`. The tab title shows the percentage while a job runs.
  - Job state lives in memory (`JOB`), so any server restart stops the job. Resume is safe.

## Repository
- GitHub: https://github.com/mouli006/Zerodha-Historical-API (public), default branch `main`. `README.md` is the user-facing guide; keep it in sync when features change.
- Never commit `.env` or anything from it. `.gitignore` covers `.env*` (except `.env.example`), `data/`, `progress.sqlite`, `errors.log`, `*.parquet`, `*.csv`, caches and editor folders. Before committing, check that no `.env` value appears in any staged file, and keep real API keys out of templates (e.g. as placeholder text). Screenshots must show demo data only.
