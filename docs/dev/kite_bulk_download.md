# Kite bulk candle download

The bulk download of historical candles for NSE equity stocks and selected indices (`backfill/runner.py`):
the form, the request chunks and rate limit, `progress.sqlite` and the run folders.

## Bulk download
- Bulk download (`/download/start`, `/download/stop`, `/download/status`): the form takes a "Stocks" checkbox list (`equity` = NSE equity stocks, plus `indices` = any of `INDEX_CHOICES`: NIFTY 50, NIFTY BANK, NIFTY FIN SERVICE, NIFTY MID SELECT, INDIA VIX; at least one required), a save folder (must be an absolute path; it is created and write-tested before the job starts; defaults to `<project>/data`), a start date, an end date (end date not in the future; max `MAX_RANGE_DAYS` = 365 days when equity is ticked, max `MAX_INDEX_RANGE_DAYS` = 20 years for indices only; the UI's "Since 2015" preset is enabled only without equity), `minute` or `day` (EOD), a speed in req/s (default 2.5; server accepts 0 < s <= 3, the UI slider is 0.5 to 3), a file format (`FILE_FORMATS`: `csv` default, or `parquet`), and "Include ETFs" / "Include trade-to-trade" options (shown only when equity is ticked). ETFs are detected by a name/symbol heuristic in `is_etf()`. A single background thread (`bulk_download`) runs the selected parts one after another in one job: indices first (segment `INDICES`, matched by tradingsymbol, in `INDEX_CHOICES` order; NIFTY 50 is token 256265), then equity. `JOB["part"]` holds the current part text ("Indices: NIFTY 50", "Equity: 1,240 / 2,942 stocks"), and the stock/chunk counters cover all parts. Equity is segment `NSE`, type `EQ`, no liquidity filter, then `is_equity()`. `series_suffix()` treats the text after the last `-` as an NSE series only when it is exactly 2 characters, so `BAJAJ-AUTO` and `NAM-INDIA` count as normal equity. Kept: no suffix, plus `-BE`/`-BZ` when "Include trade-to-trade" is ticked (off by default). Everything else is excluded: bonds, NCDs, G-secs, T-bills, SGBs and SME (`-N*`, `-Y*`, `-Z*`, `-GB`, `-GS`, `-SG`, `-TB`, `-RR`, `-SM`, `-ST`, ...). The selected count and breakdown are printed and shown on the page (`JOB["filter_info"]`); the expected count is about 2,000 to 2,300, and more than `MAX_STOCKS` (3,000) refuses to start.
  - Requests: the range is split by `make_chunks()` into Kite's per-request limit (`INTERVALS`: 60 days for minute, 2,000 for day). `RateLimiter` spaces request starts by 1/rate, halves the rate on a 429, and recovers after 20 successes. `fetch_chunk()` retries 429s and network errors with backoff `min(2**n, 60)` s, up to 10 tries, then marks the chunk FAILED. A TokenException or 403 stops the job (`AuthStop`).
  - Progress: `<folder>/progress.sqlite`, table `chunks`, keyed by `(run, symbol, chunk_from)` with `run = run_key()` = `"<interval>:<from>:<to>"`, plus `":csv"` for CSV runs, so switching format re-downloads instead of skipping, plus `":idx"` for the index part, so index and equity progress never mix (equity keys are unchanged from before). `JOB["run"]` is `job_run_key()`: the part keys joined with `" + "`, which the planner mirrors (together with the selection) to detect Resume. Status is PENDING, DONE or FAILED, committed after every chunk. An empty response counts as DONE (counted in `empty`); e.g. index 1-minute windows before ~2015-01-09. Start / Resume with the same selection, interval, dates, format and save folder skips DONE chunks. A second table, `runs` (`run` -> run folder name, start time), is described under Output. After pass 1, FAILED chunks are re-looped until none remain or a pass fixes nothing.
  - Output: each part of a job writes into its own run folder, `run_dir_name()` = `<Equity_stocks|Index_spot>_<1min|EOD>_<from>_to_<to>_started_<YYYY-MM-DD>_<HHMM>` under the save folder. `run_dir()` records it in the `runs` table of `progress.sqlite` (`run` -> `dir`) the first time a run key starts, and Resume reuses it, so a resumed run never splits across folders (runs started before this table existed get a new folder). `JOB["out_dirs"]` lists the folders for the live card, and the planner's hint mirrors the name. `save_candles(out_dir, ...)` merges into `<run folder>/<SYMBOL>/<year>.<csv|parquet>`, splitting by year, deduplicating on `date` (tz-naive IST) and sorting, with an atomic temp-file replace. `read_year()` / `write_year()` handle the two formats; CSV dates are written as `YYYY-MM-DD HH:MM:SS` for minute data and `YYYY-MM-DD` for daily. Columns: `date, open, high, low, close, volume, tradingsymbol, instrument_token`. Spaces in symbols become `_` in the folder name (`NIFTY 50` -> `NIFTY_50`) while the `tradingsymbol` column keeps the real name; reserved Windows names get a `_` suffix. `progress.sqlite` and `errors.log` live in the save folder itself (next to the run folders), so resuming needs the same save folder. Data from before run folders existed sits in `<folder>/<interval>/<SYMBOL>/` and is left alone. The default `data/` is gitignored.
