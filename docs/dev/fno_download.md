# F&O daily download

The daily NIFTY/SENSEX F&O job (`backfill/fno.py`, `nifty_daily.py`): date window and expiries, holidays,
the bhavcopy trim, zero-volume contracts, day folder names, day-count markers, the lock and the CSV layout.

## CLI
- Daily F&O CLI: `python nifty_daily.py (YYYY-MM-DD | --missing | --refetch-no-trade YYYY-MM-DD) [--folder PATH] [--speed 2.5] [--underlying NIFTY|SENSEX] [--source kite|dhan] [--keep-zero-volume | --no-keep-zero-volume] [--trim-to-bhav | --no-trim-to-bhav] [--derive-without | --no-derive-without]` (without `--folder` the folder is `config.default_fno_folder()`: the store of the keep zero-volume setting when FNO_RAW_<SOURCE> is set; `--derive-without` only acts then, with ON) (a date or --missing is required; the date is never defaulted; the trim flags default to `trim_to_bhav()` and apply to both sources in every downloading mode, `--refetch-no-trade` included). Diagnostics that write nothing (no folder check, no lock): `--inspect CONTRACT YYYY-MM-DD` prints Kite's raw candles plus the saved bhavcopy row, `--inspect-missing YYYY-MM-DD` does it for every MISSING_IN_KITE contract of the day's bhav_compare.csv and prints a table with Result ZERO_VOLUME_CANDLES / NO_CANDLES / TRADED. Exit codes: 0 finished or holiday, 1 failures or not run, 2 token missing or invalid, 3 date outside the window. argparse errors are changed to exit 1 so that 2 always means a token problem. `--source dhan` (`sign_in()`): NIFTY or SENSEX, speed up to 5, token from `dhan_api.token_ok(load_env())` (missing/expired -> 2), `DhanClient.profile()` (TokenException/PermissionException -> 2) and `data_plan_error()` (not Active -> 1); every mode, inspect included, then runs with `kite=client, user=, source="dhan"` on the Dhan folder and lock, and inspect output is relabelled Dhan. `--rename-folders [--underlying NIFTY|SENSEX|all] [--source kite|dhan|all] [--apply]` and `--update-day-count [--underlying ...] [--source ...]` (`backfill/fno_rename.py`; both default to all, `all` and `--apply` are refused in other modes, the folder must exist and is never created; both take each root's `.lock`, busy -> "Not run", exit 1): see Day folders below. Do not run it against real Kite or Dhan unless the user asks. The user runs it manually; no cron or scheduled task is set up, and none should be added.

## Download only contracts in the bhavcopy
- "Download only contracts in the bhavcopy" (`trim_to_bhav`, Kite and Dhan alike): `run_daily(trim_to_bhav=None)` means the setting (`fno.trim_default()` -> `config.trim_to_bhav()`: `.env` `TRIM_TO_BHAV` ON/OFF, else `config.TRIM_TO_BHAV` = True); `run_missing` resolves it once and passes it to every day, `refetch_no_trade` passes it on, `redownload_contract` never trims. The routes read `trim_bhav=1|0` (absent: the setting; dashboard `read_trim()`), the CLI `--trim-to-bhav`/`--no-trim-to-bhav`, and `job_fields(trim_to_bhav=)` sets `JOB["trim_to_bhav"]` (live card "Contracts: Bhavcopy only (ON) / Full list (OFF)"). When ON, run_daily calls `trim_contracts()` -> `(contracts, "ON"|"FALLBACK", reason)`: `bhav.listed_names()` gives our names of every contract of the underlying in the day's bhavcopy (saved `<day>/bhavcopy/nifty_bhav.csv`, else `fetch_bhav(budget=bhav.TRIM_BUDGET)` = 30 s for home page, tries and waits together, `BhavTimeout` after that; the download is saved like `run_bhav` does) and only those contracts are kept, traded or not (`keep_listed()`, shared with `rewrite_summary`); without it (404, any error, "bhavcopy fetch timed out") the full list is used, never a refusal. run.log gets `Contracts: trimmed to bhavcopy (kept N of M)`, `Contracts: full list (trim OFF)` or `Contracts: full list (bhavcopy not available: <reason>)`; on FALLBACK also `fallback_note()` = "Bhavcopy not available (<reason>): full contract list used", which also goes into the job message during and at the end of the run (the CLI prints it through `log`). summary.csv's last column `Trim_to_bhav` (ON / OFF / FALLBACK, blank for older days; `saved_trim()`) holds the last run's result and is kept by `rewrite_summary`, which, when it is ON, trims the saved dump the same way from the saved bhavcopy (no network), so `Listed_*` count the requested contracts on Kite and Dhan alike. Nothing is ever deleted: a full-list day re-run with ON keeps its extra files (EXTRA in the check). `fno_days` puts `Trim_to_bhav` in `days_index.csv` and the marker; never in the folder name. `fno.py` takes `source` ("kite" default, "dhan") in `fno_root`/`fno_folder` (`FOLDERS`: `<UNDERLYING>_FnO_1min` vs `<UNDERLYING>_FnO_1min_Dhan`), `read_expiries`, `record_expiries`, `load_window`, `holidays_logged`, `missing_dates`, `acquire_lock`, `run_key` (Dhan: `fno-dhan:NIFTY:NSE_FNO:<date>`), `exchange_of`, `job_fields` (sets `JOB["source"]`, reset per job via `COUNTERS`), `run_daily` and `run_missing` (which also accept a ready `kite=`/`user=`). The default keeps every Kite folder, key and message unchanged. `bhav.py` (`bhav_dir`, `read_check`, `unchecked_days`, `run_bhav`, `list_days`, `compare_rows`, `diff_rows`), `bhav_export.py` (every reader and `export`; `relabel()` renames `Kite*`/`KITE` to Dhan in Dhan output and file names get `_dhan`) and `fno.redownload_contract` (`kite=`, `source=`; `DhanClient.learn()` reads the instrument type from the saved `instruments_NSE_FNO.csv`) take the same `source`. The bhavcopy routes read `?source=` (`fno_source()`; `signed_in(source)`: Kite session, or a valid Dhan token) and pass it on, including to `locked_fno` and `refresh_live_summary`. The comparison files inside a day keep their `Kite_*` column names for both sources. `refetch_no_trade`, `inspect_contracts` (`kite=`, `source=`), the CLIs (`--source dhan`) and `fno_loader` (`source=`) work on both. `tests/test_dhan_bhav.py` covers the Dhan check, exports, routes and re-download.

## Daily F&O job
- Daily F&O job (`backfill/fno.py`, `run_daily`):
  - `UNDERLYINGS = {"NIFTY": ("NFO", 50), "SENSEX": ("BFO", 100)}` (Kite exchange, strike step for ATM) and `EXCHANGE_OF = {"NIFTY": "NSE", "SENSEX": "BSE"}` (`exchange_name()`: whose bhavcopy checks it; messages say NSE/BSE from it). Every function takes `underlying`; SENSEX goes to `SENSEX_FnO_1min/`, run key `fno:SENSEX:BFO:<date>`, its own lock. The dashboard's F&O card has an Index switch (NIFTY | SENSEX, `boot.fno.underlyings`, `und` state in `App`, remembered in localStorage `fno-underlying`) that also drives `Q.underlying` for the `BhavCard` and every `/fno/*` call; the CLIs take `--underlying SENSEX`. Dhan does NIFTY and SENSEX too (`dhan.UNDERLYINGS`; `fno.exchange_of(u, "dhan")` is NSE_FNO / BSE_FNO, so Dhan SENSEX goes to `SENSEX_FnO_1min_Dhan/`, run key `fno-dhan:SENSEX:BSE_FNO:<date>`, `instruments_BSE_FNO.csv`, and its trim uses BSE's bhavcopy; the Dhan page shows the same Index switch). Output goes to `<save folder>/<UNDERLYING>_FnO_1min/<day folder>/{futures,options}/`, plus `instruments_<EXCH>.csv`, `summary.csv`, `run.log`, and `holidays.log` one level up.
  - Day folders: `<YYYY-MM-DD>_exp-<nearest option expiry>_<withZeroVol|noZeroVol>_dl-<YYYY-MM-DD>_<HHMM>` (`day_folder_name(day, expiry, keep_zero, created_at)`, IST, no colons), e.g. `2026-10-12_exp-2026-10-13_withZeroVol_dl-2026-10-13_2319`; older days are plain `YYYY-MM-DD` and every reader accepts both. Never build `<root>/<date>` by hand.
    - Helpers in `fno.py`: `parse_day_folder(name)` ((day, expiry, keep_zero, created) or None; old names give (day, None, None, None)); `day_folders(root)` ({day: name}, creates nothing, raises `DayFolderError` listing the folders when a day has two); `find_day_dir(root, day)` / `day_dir(data_root, underlying, run_date, source)` (path or None); `nearest_option_expiry()` (CE/PE, expiry >= day); `mark_with_zero_volume(day_dir)` (returns the path to use from then on).
    - `run_daily` reuses the existing folder of the date whatever its name. Only when there is none does it take the expiry from the run's full instrument list and create the folder with `now_ist()` (the expiry comes before the bhavcopy trim); no expiry -> `"error"`, nothing created; duplicates -> `"error"`.
    - The one allowed rename: `noZeroVol` -> `withZeroVol`, in `finish_day_folder()` from `download_day`'s `finally` (after run.log and the db are closed) when keep_zero is ON, and after `redownload_contract(keep_zero=True)`; never when the save folder is a with / without store (`fno.in_split_store()`). The caller holds the lock. An OFF run never renames back, and dl never changes. A failed rename (folder open in Explorer) is reported and retried by the next ON run. Code holding a day path across a run (`refetch_no_trade`, the redownload route) looks the folder up again.
    - run.log gets each run's "started" and "Keep zero-volume contracts" lines, and a "Re-download of X ... started ... IST, keep zero-volume contracts ON/OFF" line per re-download.
    - Holidays still remove a folder the run created. progress.sqlite run keys stay keyed by date.
    - `run_bhav` raises `BhavError` ("download it first") when the day has no folder and never creates a bare `<date>/bhavcopy/`; `bhav_dir()` returns None then. `list_days()` entries add `folder`, `expiry`, `zero_volume` ("with"/"no"/"") and `downloaded`; the BhavCard table shows them.
    - `dashboard`/`dhan` blueprints turn `DayFolderError` into a JSON `error`; the CLIs print it and exit 1. `read_expiries` takes `first_seen` of a dump from the parsed folder day.
    - Day count (`backfill/fno_days.py`): `write_day_count(root)` writes `days_index.csv` (`INDEX_COLUMNS`) and `_DAYS-<n>_<first>_to_<last>.txt` (`_DAYS-0.txt` when empty; totals line, then a table) atomically, then removes only other files matching `MARKER_RE`. It runs when a run created, renamed or (holiday) removed its folder, after `--rename-folders --apply` and from `--update-day-count`, never from readers. `/download/fno-window` and `/dhan/fno-window` return `days` = `day_summary(root)` (read only) for the F&O card's "Saved days" line. The count is never put in the root folder's name (the open `.lock` blocks renaming the root on Windows).
    - `--rename-folders` (old-style folders only; dry run prints `old -> new  (exp: ...; zero volume: ...; dl: ...)` and writes nothing, not even the marker): exp from summary.csv's "Current week" row, else `expiries_seen.csv`; zero volume `withZeroVol` if summary.csv `Keep_zero_volume` ON, or run.log any "Keep zero-volume contracts: ON", or a Kept = Y row in `zero_volume_contracts.csv`, else `noZeroVol` if summary.csv OFF or run.log only OFF; dl from run.log's first `started ... IST`, else `st_ctime` in IST. Unknown exp or zero-volume setting -> SKIPPED and listed. `--apply` renames one folder at a time, stops on the first error listing what was renamed, then writes each touched root's day count.
  - Everything date- or time-related uses `IST = ZoneInfo("Asia/Kolkata")` explicitly (`now_ist`, `today_ist`, `to_ist`), never local time, because the server may run on UTC. The run date is always picked by the user: the dashboard's date picker starts empty, the route requires `date`, `date_from`+`date_to` (or `missing=1`), and the CLI requires a date or `--missing`. Never default it to today. `too_early()` refuses today before `READY_AT` = 15:40.
  - Date window (`date_window`, `window_error`): allowed dates are [previous expiry + 1, today], because on those days every contract is still live, so the day is complete. There is no PARTIAL marking; dates outside are refused (`"outside_window"`, CLI exit 3). Current week expiry = earliest live expiry in today's dump (`live_expiries`). Previous expiry = latest expiry in `expiries_seen.csv` (`read_expiries`/`record_expiries`; seeded from saved `instruments_*.csv` dumps if missing) before the current one. Falls back to `weekday_before(current, weekday)` (`config.weekly_expiry_weekday(underlying)`: .env `WEEKLY_EXPIRY_WEEKDAY_<UNDERLYING>`, for NIFTY also the older `WEEKLY_EXPIRY_WEEKDAY`; defaults `WEEKLY_EXPIRY_DEFAULTS` NIFTY TUE, SENSEX THU), with `estimated=True` and a WARNING (`window_note`), when history has nothing on or after fallback - 1 day. That guard keeps stale history from opening the window too early; keep it. `load_window()` fetches the dump, records history and returns the window. `run_daily` checks too_early, then the token (`connect`), then the window, all before creating the day folder.
  - `missing_dates()` lists window dates without a complete day (summary.csv and no non-DONE rows), minus `holidays_logged()` and today before READY_AT. It creates nothing on disk (the dashboard calls it while the user types a folder). `run_missing()` runs them oldest first with one Kite session, dump and window (`run_daily(..., kite=, instruments=, window=, last=False)` keeps `state` running between days). `run_missing(dates=[...])` runs a picked range instead (`range_dates()`): every day in it, saved or not (saved contracts are skipped), minus logged holidays and today before READY_AT; a day outside the window refuses the whole range (`"outside_window"`), and messages say "Range days".
  - Dashboard: `GET /download/fno-window?folder=` (`fno_window()`, live expiries cached per IST day in `LIVE`; it reads the folder's history but writes nothing) feeds the card: date min/max, current week expiry, the expiry-day warning, and the missing days for the "Download all missing days" button. `POST /download/fno-start` takes `date`, a range `date_from`+`date_to` (`fno.parse_pick()`; the same day twice is one day; first/last day must pass `window_error`, last day `too_early`; run key `fno:NIFTY:NFO:<from>_to_<to>`, `fno_date` ""), or `missing=1`, `speed`, `folder`, `keep_zero=1|0`, and `refetch=1` (with a single date: `refetch_no_trade`; refused with a range or unless `keep_zero=1` and the day has summary.csv).
  - Cross-process lock: `acquire_lock()` takes an OS lock (`msvcrt.locking` past EOF / `fcntl.flock`) on `<UNDERLYING>_FnO_1min/.lock`. It is held by both the CLI and the dashboard thread and dropped by the OS if the process dies. Do not switch to PID files (`os.kill(pid, 0)` terminates the process on Windows).
  - Order: too_early, `kite.profile()` token check (`TokenException`/`PermissionException` -> `"auth_failed"`), the instrument dump and window check (all before the day folder is created), `select_contracts()` (`name == underlying`, FUT/CE/PE, expiry >= date), names, then the holiday check (the nearest future returns no candles and, on Kite, so does the spot index (`spot_traded()`: Kite `SPOT_TOKENS` NIFTY 50 256265, SENSEX 265; Dhan `DhanClient.spot_token()`; asked only when the future is empty, because a SENSEX future can go a trading day untraded) -> log it, delete the day folder only if this run created it and it has no contract CSVs, return `"holiday"`), then every contract via `fetch_chunk(..., oi=True, max_tries=3)` over `WINDOW` 09:00-16:00 (all rows kept), plus one retry pass for FAILED, then `build_summary()`. Kite and Dhan runs then get the day's bhavcopy (`run_daily(bhav_check=)`, default `fno.AUTO_BHAV and not refetch`; the trim's saved download is reused on both brokers): `fetch_day_bhav()` reuses `bhav.listed_names()` (saved file, else a download of at most `bhav.CHECK_BUDGET` = 60 s, saved into `<day>/bhavcopy/`); then `check_day_bhav()` runs `bhav.check_saved()` after summary.csv is written. Not published / errors: run.log and `bhavcopy.log` get the reason, the day stays pending, and the run's status never changes. `tests/conftest.py` sets `fno.AUTO_BHAV = False` for every test; tests that need it turn it on and stub `bhav.fetch_bhav`. `SUMMARY_COLUMNS`: `Listed_strikes`/`Listed_contracts` count the contracts the run requested (the dump, trimmed to the bhavcopy when `Trim_to_bhav` is ON); `Traded_strikes`/`CE_files`/`PE_files` are counted from the files on disk at the end (so resumed runs count earlier files), never from this run's writes.
  - Names come from expiry/strike (`contract_name`), never from Kite's tradingsymbol. A naming error (non-whole strike) marks that contract FAILED. Duplicates never overwrite (feature 26): contracts sharing a tradingsymbol or building the same file name are all FAILED with reason `DUPLICATE_NAME` before any request (logged in run.log and errors.log), and `save()` refuses to write a path another contract already wrote this run (`DuplicateWrite`: the earlier file is removed and both are FAILED `DUPLICATE_NAME`). Progress is kept in `progress.sqlite` under run key `fno:<UNDERLYING>:<EXCH>:<date>`, keyed by tradingsymbol. A contract is skipped if it is DONE or its file exists. Contracts with no candles never get a file (`JOB["empty"]`, reason `NO_CANDLES`). Kite builds volume from differences of the day's cumulative volume, so a contract that traded once can come back with candles (right price and OI) whose volumes are all 0 (verified 2026-10-12: all 56 MISSING_IN_KITE contracts of 2026-10-07). "Keep zero-volume contracts" (`keep_zero`; default `config.KEEP_ZERO_VOLUME`, .env `KEEP_ZERO_VOLUME` ON/OFF overrides; dashboard switch, CLI flags) writes those rows exactly as Kite returns them; OFF gives no file and reason `ZERO_VOLUME`. Counts: `JOB["zero_kept"]` / `JOB["zero_skipped"]`; both modes list them in `<day folder>/zero_volume_contracts.csv` (`ZERO_VOLUME_COLUMNS`, merged across runs). The reason is stored in the `reason` column of `chunks` (added by `open_db`; NULL for older days). With keep_zero ON a run re-requests DONE contracts without a file whose reason is ZERO_VOLUME; `refetch_no_trade()` (dashboard "Re-check no-trade contracts", `--refetch-no-trade`, needs ON and a saved day) re-requests every DONE contract without a file whatever its reason, then runs `bhav.check_saved` if the bhavcopy is saved. run.log records the setting, and summary.csv's `Keep_zero_volume` column (before `Trim_to_bhav`) holds the last run's setting (kept by `rewrite_summary`).
  - CSV: `HEADER` `Ticker,Date,Time,Open,High,Low,Close,Volume,OI`, LF line endings, `Date` as YYYYMMDD, `Time` as HH:MM:SS IST, numbers via `fmt_num` (whole floats without `.0`), matching the user's Accelpix files.
  - The live card reuses the backfill keys (`stocks_*`/`chunks_*` = contracts, `completed` = files written) plus `fno_date`, `fno_underlying`, `fno_exchange`, `fno_summary` (summary.csv rows) and `fno_futures` (per-future stats). The dashboard's `FnoCard` has its own save folder (`fnoFolder` state in `App`, shared with `BhavCard`; input `#fno-folder` plus Browse via `/browse-folder`), started from `boot.form.folder`; the planner's `folder` state lives in `App` and is not shared with it.
  - A past day's dump is saved as `instruments_<EXCH>_fetched_<today>.csv` because it is today's list.
  - `backfill/fno_loader.py` reads saved days back for backtests: `load_day`, `load_contract` (minute bars; `fill_oi()` per file: OI 0 in a contract with non-zero OI that day becomes NaN and is forward-filled from the previous minute, `OI_filled` True on those rows, leading zeros stay NaN, all-zero days untouched, never across days; `fill_oi=False` gives raw values; files are never written) and `load_eod` (the saved bhavcopy by our contract names: `EOD_COLUMNS` with Close, Last, Settle, OI in shares, Volume_contracts, Lot). Backtests should take the EOD close, settlement price and final OI from `load_eod`, not from Kite's last bar.
