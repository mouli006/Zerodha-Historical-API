# Architecture

What the app is, how the code is laid out, how the pages are built (React via CDN, no build step),
where config lives (`.env`) and the repository rules. Read this first when you need the big picture.

## Overview
Flask web app that logs a user in through Zerodha Kite Connect v3 (`kiteconnect` Python SDK), then shows a dashboard for bulk-downloading historical candles for all NSE equity stocks and selected NSE indices (NIFTY 50 spot etc.) (https://kite.trade/docs/connect/v3/historical/) and watching the job's progress live. It also runs a daily F&O job for NIFTY (Kite NFO) and SENSEX (Kite BFO) (1-minute candles with OI for every live future and option, saved in the Accelpix layout) from a dashboard card or `nifty_daily.py`, and checks each saved day against the exchange's F&O bhavcopy, NSE's for NIFTY and BSE's for SENSEX (dashboard "Bhavcopy check" card or `nifty_bhav.py`). `nse_reference.py` collects NSE delisting, suspension and merger reference data since 2015 (no broker login), and `cm_bhav.py` downloads NSE's equity (CM) bhavcopy for every trading day since 2015 (no broker login). The UI calls itself "Kite Backfill". Everything runs locally on one machine.

## Install and run
- Install: `pip install -r requirements.txt` (flask, kiteconnect, requests, pandas, pyarrow, openpyxl, tzdata, pytest, pdfplumber, playwright), then `playwright install chromium` for `nse_reference.py`'s fallback browser.
- Run: `python app.py`, which serves http://127.0.0.1:5000. Debug is off, so neither `.py` nor template edits are picked up until the server is restarted (templates are cached). Restarting stops a running download; Resume is safe.

## Code layout
- Code layout:
  - `app.py` only creates the Flask app, sets the secret key and registers the three blueprints.
  - `config.py` holds paths and the `.env` helpers (`load_env`, `save_env`, `credentials`, `dhan_credentials`, `secret_key`, `data_dir`, `weekly_expiry_weekday`, `keep_zero_volume`, `trim_to_bhav`) and the defaults `KEEP_ZERO_VOLUME` and `TRIM_TO_BHAV`.
  - `auth.py` is the `auth` blueprint: `/`, `/login`, `/callback`, `/logout`.
  - `dhan.py` is the `dhan` blueprint: `/dhan`, `/dhan/login`, `/dhan/logout`, `/dhan/dashboard`, `/dhan/fno-window`, `/dhan/fno-start` (Dhan sign-in and the Dhan F&O page; see below).
  - `dashboard.py` is the `dashboard` blueprint: `/success`, `/download/*` (incl. `/download/fno-start` and `/download/fno-window`), `/fno/*` (bhavcopy check), `/browse-folder`.
  - `nifty_daily.py` (repo root) is the CLI for the daily F&O job.
  - `nifty_bhav.py` (repo root) is the CLI for the NSE bhavcopy check (`backfill/bhav.py`).
  - `fno_store.py` (repo root) is the CLI for `backfill/fno_store.py` (move-raw, split-stores), `backfill/fno_derive.py` (derive-without, compare-variants), `backfill/fno_clear.py` (clear, restore), `backfill/fno_import.py` (import) and `backfill/fno_publish.py` (publish); `backfill/fno_backtest.py` reads the store.
  - `nse_reference.py` (repo root) is the CLI for the NSE delisting / suspension / merger reference (`backfill/nse_ref/`).
  - `cm_bhav.py` (repo root) is the CLI for `backfill/cm_bhav.py` (NSE equity bhavcopy store).
  - The `backfill/` package is the download engine and has no Flask imports. It contains `job.py` (`JOB`, `JOB_LOCK`, `STOP`), `fetch.py` (`INTERVALS`, `make_chunks`, `RateLimiter`, `fetch_chunk`, the stop exceptions), `instruments.py` (equity/ETF filter, `INDEX_CHOICES`, `is_index`), `storage.py` (`run_key`, `job_run_key`, `check_folder`, candle files, `progress.sqlite`, `errors.log`), `runner.py` (`bulk_download`), `fno.py` (daily F&O job), `dhan_api.py` (`DhanClient`, a Kite-shaped DhanHQ v2 client, and `fetch_profile`), `bhav.py` (NSE bhavcopy check), `bhav_export.py` (downloads of the check), `fno_days.py` (the day-count marker and `days_index.csv`), `fno_rename.py` (`--rename-folders`, `--update-day-count`), `fno_loader.py` (reads saved raw F&O days back), `fno_store.py` (move-raw, split-stores), `fno_derive.py` (the without-zero-volume copy of a with day), `fno_clear.py` (archive one underlying's F&O data, and restore it), `fno_import.py` (replace one underlying's live data with a prepared copy), `fno_publish.py` (raw -> backtest store) and `fno_backtest.py` (reads the backtest store), plus the `nse_ref/` subpackage (NSE reference data); see below. `locks.py` re-exports `RunLock` and `LockBusy` from `fno.py` and is the import point for all non-F&O code (the lock can later move there without touching callers). The `equity/` subpackage is the home for new equity modules (security master, split/bonus factors, exits, index membership); it never imports F&O modules (`tests/test_equity_imports.py`).
  - Templates use blueprint endpoint names in `url_for`, e.g. `auth.login` and `dashboard.download_start`.
- Templates extend `templates/base.html`, which contains the shared CSS (dark theme, Manrope font) and loads React 18 (UMD, cdnjs) and `htm` (unpkg) from CDNs: no Node, no build step, no static files. Each page passes its data to React as JSON in `<script id="boot" type="application/json">{{ ...|tojson }}</script>` and renders into `#root` with htm tagged templates. The React script bodies are wrapped in `{% raw %}...{% endraw %}` because htm's `${{...}}` style objects clash with Jinja; use `className`/camelCase SVG attributes, not `class`/`stroke-width`. `base.html` also defines shared `Toasts`, `useToasts`, `Logo` and `BrokerTabs` (the Zerodha / Dhan tab links at the top of both sign-in cards, `/` and `/dhan`). The UI needs internet access to load React and fonts.

## Config and tokens
- Config lives in `.env`, which is gitignored. It is read and written by the hand-written `load_env()` / `save_env()` in `config.py`. `python-dotenv` is deliberately not used. Credentials are read again on every request through `credentials()`, so changing them needs no restart. Keys: `EQUITY_DATA_DIR` (optional; `config.equity_data_dir()`, the equity bhavcopy and NSE reference folder), `KITE_API_KEY`, `KITE_API_SECRET`, `KITE_ACCESS_TOKEN` (written by `/callback`, removed by `/logout`), `KITE_DATA_DIR` (the last save folder used for bulk download), and `FLASK_SECRET_KEY` (generated automatically on first import; keeps sessions valid across restarts). Optional `WEEKLY_EXPIRY_WEEKDAY` / `WEEKLY_EXPIRY_WEEKDAY_<UNDERLYING>` (MON..SUN; NIFTY TUE, SENSEX THU by default) are used only for the F&O date-window fallback, and optional `KEEP_ZERO_VOLUME` (ON/OFF) overrides `config.KEEP_ZERO_VOLUME` (True), and optional `TRIM_TO_BHAV` (ON/OFF) overrides `config.TRIM_TO_BHAV` (True), and optional `DERIVE_WITHOUT_ZERO_VOLUME` (ON/OFF) overrides `config.DERIVE_WITHOUT_ZERO_VOLUME` (True; `config.derive_without()`, all three through `on_off_setting()`). `KITE_DATA_DIR` is also the starting folder of the F&O card and the CLIs' default `--folder`, unless the optional `FNO_RAW_KITE` / `FNO_RAW_DHAN` are set (`config.fno_raw_dir(source, variant=None, env=None)`; with them set they are the base of the two zero-volume stores, see F&O backtest store; boot `fno.folder` on the Kite page, the Dhan page's form folder unless the last job was a Dhan F&O job; `nifty_daily.default_folder(source)`, also per source for `--rename-folders`/`--update-day-count --source all`; `nifty_bhav.py`). With the key set, an F&O start no longer writes `KITE_DATA_DIR`. Optional `FNO_BACKTEST_DIR` (`config.fno_backtest_dir()`) is the backtest store (see below). `.env.example` lists the keys with blank values.
- `save_env()` is atomic and thread-safe: under the module lock `ENV_LOCK` it writes the whole file (`KEY=value`, LF) to `.env.tmp` next to `.env`, fsyncs it and `os.replace`s it (`replace_file`, retried `REPLACE_TRIES` times when Windows reports the file busy, then a clear error without the contents). On any failure the temp file is removed and the old `.env` is left unchanged.
- The access token is kept in the Flask session cookie and in `.env`. The bulk job reads it from `.env`. Never print or log it or the secret. Kite tokens expire daily, so the user must log in again each day.
- Historical data is included in the paid Kite Connect plan (Rs 500/month). API errors (e.g. an expired session) stop the job or fail chunks; they appear in the live card's status message and in `<folder>/errors.log`.

## Repository
- GitHub: https://github.com/mouli006/Zerodha-Historical-API (public), default branch `main`. `README.md` is the user-facing guide; keep it in sync when features change.
- Never commit `.env` or anything from it. `.gitignore` covers `.env*` (except `.env.example`), `data/`, `progress.sqlite`, `errors.log`, `*.parquet`, `*.csv`, caches and editor folders. Before committing, check that no `.env` value appears in any staged file, and keep real API keys out of templates (e.g. as placeholder text). Screenshots must show demo data only.
