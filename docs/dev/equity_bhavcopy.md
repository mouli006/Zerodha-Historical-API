# NSE equity (CM) bhavcopy store

Downloads NSE's equity bhavcopy for every trading day since 2015 into per-year parquet files
(`backfill/cm_bhav.py`, `cm_bhav.py`). No broker login; it is the broker-independent reference.

## CLI
- Equity bhavcopy CLI: `python cm_bhav.py (YYYY-MM-DD | --from D --to D | --missing | --offline) [--folder PATH] [--sleep 1.5] [--force] [--no-browser]` (no login; folder default `config.equity_data_dir()`; `--offline` runs alone; weekends, future dates, from > to and a missing mode are argparse errors). Exit codes: 0 all done (today pending is not a failure), 1 some days failed (each printed with its URL and the `raw\<YYYY>\` path to save it under), 2 bad arguments (argparse's own code is kept here) or `LockBusy`. Run manually; no cron.
- Weekend sessions: `python cm_bhav.py --special [--apply] [--folder PATH] [--sleep 1.5] [--no-browser]` asks NSE
  only for the Saturday / Sunday dates of `manual_special_sessions.csv`. The dry run saves nothing (not even the
  lock) and lists the raw/ zips and parquet years an `--apply` would write; `--apply` saves the files found like a
  normal day, and a 404 records nothing (no `holiday`). Every other mode still asks weekdays only. See
  docs/dev/special_sessions.md.

## Store
- NSE equity (CM) bhavcopy store (`backfill/cm_bhav.py`, `cm_bhav.py`, run by hand):
  - **Rules:** no broker at all (NSE's public archive only; no Kite/Dhan login, token or call). It is the exchange's official record and stays broker-independent: Kite and Dhan daily equity data will later be compared against it (not built yet). It never touches F&O code, folders or `progress.sqlite` files, nor the Kite equity candle download. It imports only `RunLock`/`LockBusy` from `backfill/fno.py` (through `backfill/locks.py`) and the fetch pieces of `backfill/nse_ref/fetch.py`.
  - Folder `config.equity_data_dir()` (`.env` `EQUITY_DATA_DIR`, else `KITE_DATA_DIR`, else `./data`; `nse_reference.py` uses the same default, so `reference/` sits next to it): `<folder>\NSE_CM_bhav\` with `raw\<YYYY>\<zip as downloaded>` (never changed; a zip saved there by hand is used as is), `<YYYY>.parquet` (`SCHEMA`: `date, symbol, series, isin, open, high, low, close, last, prev_close, volume, turnover, trades, fin_id, format`; every series; sorted by date, symbol, series; atomic), `days.csv` (`DAYS_COLUMNS`, from the db), `holidays.log`, `cm_bhav.log`, its own `cm_bhav_progress.sqlite` (table `days`: date PK, status ok/holiday/failed/pending, format, file relative to the store, url, rows, eq_be_bz_rows, downloaded_at IST, note; committed per day) and its own `.lock` (`RunLock`).
  - `SOURCES` (verified on real files): `old` = `content/historical/EQUITIES/<YYYY>/<MON>/cm<DD><MON><YYYY>bhav.csv.zip` (`OLD_HEADER` plus an empty trailing column, TIMESTAMP `03-MAR-2021`) and `udiff` = `content/cm/BhavCopy_NSE_CM_0_0_0_<YYYYMMDD>_F_0000.csv.zip` (`UDIFF_HEADER`, its own copy of the 34 UDiFF columns, `Sgmt` CM / `FinInstrmTp` STK enforced). `formats_for()`: old before `SWITCH_FROM` (2024-07-01), UDiFF then old inside `SWITCH_FROM..SWITCH_TO` (2024-07-12), UDiFF after.
  - `CmClient(NseClient)`: `TRIES` = 3 with backoff, `Throttle(gap=--sleep)`, the body must start with `PK`. **Only a real HTTP 404 is `NotFound`** (all formats 404 -> past weekday `holiday`, logged once in `holidays.log`, skipped later unless `--force`; today -> `pending`). A 200 with a page instead of the zip is treated like 401/403 (`Blocked` -> headless Chrome, else `FetchError`) -> `failed`, retried next run, listed with the drop-in path (its `raw\<YYYY>\` is created). Today before `READY_AT` (19:00 IST) is `pending` with no request. `--force` re-downloads (atomic `write_bytes`); a failed re-download keeps the saved zip.
  - `parse_zip()` raises `BadFile` naming the file: one CSV in the zip, exact header (unknown/missing columns listed), one date equal to the day, no duplicate (symbol, series), open/high/low/close > 0, high >= low, every number present except a blank last price outside `MAIN_SERIES` (EQ/BE/BZ), which is stored as null with `blank_last_note()` in the day's note (NSE leaves `LastPric` blank on a debt row or two, e.g. 2024-07-05 NT, 2024-07-08 AT); turnover rounded to 2 decimals. A bad day is `failed`, the others go on; the CLI lists failed checks (the zip exists) apart from failed downloads.
  - After the days, `stale_years()` (parquet dates != ok days in the db, or a year that got a day) are rebuilt from raw/ (`rebuild_year`, also in `finally`, so a stopped run keeps what it did). `--offline` scans `raw\` (`parse_file_name`), records every zip and rebuilds.
  - `report()`: per year trading days, holidays, failed, pending, rows, EQ/BE/BZ rows per day min/median/max, the format switch (first UDiFF / last old day), and years with more than `HOLIDAY_FLAG` (18) weekday holidays flagged with their dates.
