# F&O raw and backtest store

The with / without zero-volume raw stores, derive-without, move-raw, split-stores, publish to the backtest
store and its loaders, clear/restore and import (`fno_store.py` and `backfill/fno_store|derive|publish|backtest|clear|import.py`).

## CLI
- F&O store CLI (`fno_store.py`, run by hand): `move-raw --from PATH [--from PATH ...] --source kite|dhan [--to PATH | --variant with|without] [--apply]`, `split-stores [--source kite|dhan|all] [--apply]`, `derive-without --source kite|dhan [--underlying NIFTY|SENSEX|all] [--from D] [--to D] [--with PATH] [--without PATH] [--apply]`, `compare-variants` (same options, no `--apply`), `clear --underlying NIFTY|SENSEX (required) [--source kite|dhan|all] [--variant with|without|all] [--no-backtest] [--archive-to PATH] [--apply] [--delete] [--yes]`, `restore --from PATH [--apply]`, `import --from PATH --underlying NIFTY|SENSEX (required) [--apply] [--yes]` and `publish [--raw-kite PATH] [--raw-dhan PATH] [--out PATH] [--variant with|without|both] [--underlying NIFTY|SENSEX|all] [--from D] [--to D] [--prefer kite|dhan] [--force] [--prune] [--prune-old-layout]`; see F&O backtest store below. Exit codes: 0 done or dry run, 1 not run / stopped / a busy root / a failed day / (compare-variants) a difference (argparse errors too).

## With / without zero-volume stores
- With / without zero-volume stores (F&O only): `FNO_RAW_KITE` / `FNO_RAW_DHAN` are bases, each holding two ordinary save folders `config.VARIANTS` = `with_zero_volume` (keep zero-volume ON) and `without_zero_volume` (OFF); `FNO_BACKTEST_DIR` likewise holds `with_zero_volume\<UNDERLYING>\` and `without_zero_volume\<UNDERLYING>\`.
  - Resolution (`config.py`): `fno_target(folder, source, keep_zero, derive, env)` -> (folder, derive_to): only a folder equal to the base (`is_fno_base`, normcase/normpath) becomes `fno_raw_dir(source, variant_of(keep_zero))`, and derive_to (the without store) is set for ON when `derive` (None: `derive_without()`) is on; any other folder is used as is and never derived. `store_variant(folder)` (by name), `store_base()` (Dhan page: a remembered store folder shows as the base), `split_stores_on(source)`, `default_fno_folder(source, keep_zero)` (CLIs). Without the key: no stores, old behaviour. `fno.store_mismatch(data_root, keep_zero)` refuses an ON run into a without store and vice versa (`download_day`, `run_missing`, `redownload_contract`, routes, CLI).
  - Routes: `/download/fno-start`, `/dhan/fno-start` and `/fno/redownload` resolve with `fno_target` (form `keep_zero`, `derive=1|0`); both fno-window routes resolve when `keep_zero` is sent. Boot `fno.base`, `fno.variants`, `fno.derive_without`. The UI (`storeOf()` in success.html) resolves the same way: `FnoCard` sends the typed folder (so the server can tell it is the base) and shows "Saving to <store>" plus the "Also save a without-zero-volume copy" switch (`deriveWithout`, base and ON only); `App` loads the bhav list from the resolved store, `BhavCard` reads it and re-downloads with `rawFolder`. Live card: "Without-zero-volume copy" when `JOB["derive_without"]`.
  - Auto-derive: `fno.run_daily(*args, derive_to=None, **kwargs)` wraps `download_day` (the old run_daily); after status `finished` with keep_zero ON and derive_to it calls `fno_derive.after_run()` and `report_derive()` (with day's run.log, console, `JOB["message"]`); `finished_failures` gets "not made: some contracts failed". `run_missing`, `refetch_no_trade` (after its bhavcopy re-check) and `redownload_contract` (when a file was saved) take `derive_to` too.
  - `backfill/fno_derive.py` (**equivalence rule: without = with minus the files whose total volume is 0**; the reverse is impossible): `zero_volume_files()` (must equal the Kept = Y rows of `zero_volume_contracts.csv`, else `DeriveError`, nothing written); `derive_day(with_day, without_data_root, underlying, source)` builds `<noZeroVol name>.part` (same exp/dl; old-style/noZeroVol refused; a stale `.part` is removed first): copy minus zero files and `bhavcopy/exports`, Kept = N, summary.csv `Keep_zero_volume` OFF, run.log "Derived from ... removed N zero-volume contracts", `derived_from.txt`, then `bhav.check_saved()` (else `rewrite_summary`), rename into place, `write_days_summary`, then the progress rows (after the rename on purpose: DONE rows without the folder would make an OFF run skip contracts; zero-volume ones DONE/ZERO_VOLUME), then the day count; any error removes the `.part`. `after_run()` takes the without root's lock (busy -> not made) and derives, or compares an existing day (`compare_days`, `diff_line`: never overwritten). `derive_without()` (CLI; dry run lists "would derive ... remove N zero-volume files of M") and `compare_variants()` (derives into a `TemporaryDirectory`, writes nothing in raw).
  - `backfill/fno_store.py`: `plan(..., pick=)` (True move / None leave out / reason REFUSED), `take_locks()`, `store_pick(variant)` (move-raw into a store by the `--to` folder's name), `day_zero_volume()` (name, else `fno_rename.zero_volume_setting`), `split_stores(sources, env, apply)` (the base's roots into both stores with move-raw's merges, unknown old-style SKIPPED, "only noZeroVol ... can't be derived" listed). `report_and_apply` opens each `r["to"]`'s progress.sqlite.
  - `fno_publish.publish_variants(raw_bases, out, variants, ...)` runs `publish()` per store (`<base>\<variant>` -> `<out>\<variant>`), lists `old_layout()` (`<out>\<UNDERLYING>` with a manifest) and removes it only with `prune_old_layout`. days.csv adds `kite_derived` / `dhan_derived` (`derived_from.txt`; manifest `derived`, refreshed for unchanged days). `fno_backtest` functions take `variant="with"|"without"` (`store_root(root, variant)` = `<root or FNO_BACKTEST_DIR>\<variant folder>`).

## Clear / restore
- Clear / restore (`backfill/fno_clear.py`, `fno_store.py clear|restore`, run by hand): `plan_clear(underlying, sources, variants, backtest, env)` reads only: the underlying's roots under each `<FNO_RAW_<SOURCE>>\<variant>` (plus the old `<base>` root with all variants), per root the items (day folders, `*.part` folders, `MARKER_RE` files, `days_index.csv`, `bhavcopy.log`) and the kept rest (`expiries_seen.csv` for the window, `holidays.log`, `.lock`), the progress rows per save folder (`prefix()`: `fno:<U>:` / `fno-dhan:<U>:`, exact `substr` match, so range keys too), and the backtest folders (`<FNO_BACKTEST_DIR>\<variant>\<U>`, old `<FNO_BACKTEST_DIR>\<U>`; regardless of `--source`). `clear()` refuses without an underlying, `--delete` without `--apply` or a terminal, unset bases, a running in-process job, an existing archive folder or a busy root (`take_locks`); prints everything plus `window_lines()` (offline: live = saved expiries >= today IST, `fno.date_window` with `weekly_expiry_weekday`; no live expiry -> every day treated as lost); `--apply` asks `y` when days are lost (unless `--yes`) and, for `--delete`, the typed `DELETE <U>`. Apply order: rows copied to `<archive>\<rel save folder>\progress_<u>.sqlite`, items moved (`move_item`: `fno_store.move_day` for folders, rename or copy+size check for files) with `clear_manifest.json` rewritten after each, then the live rows deleted, day counts rewritten (also after an error) and `CLEARED.txt` written. Archive default `<home_of(env)>\archive\<YYYY-MM-DD_HHMM IST>_clear_<U>` (home = common folder of the .env bases, never a drive root), items at `rel_to(path, home)`. `restore(archive, apply)`: markers skipped (rewritten), items whose original path exists or that are missing from the archive REFUSED (exit 1), rows per run key only when the live db has none, or counted as present when the archived rows are already there.

## Import
- Import (`backfill/fno_import.py`, `fno_store.py import`, run by hand): `find_stores(src, underlying)` maps `--from` subfolders (`source_of_name`: exactly one of kite/dhan in the name; `variant_of_name`: `without zero volume`/`with zero volume` prefix, `_` read as space, "without" checked first) to {(source, variant): `fno_root`}, listing the rest as not recognised. **The source is only read, never locked** (taking a `.lock` rewrites its owner text). `inventory()` per store: `fno.day_folders` (duplicates -> error), `completeness()` (summary.csv + run.log's last "F&O 1-minute run for" block has `=== Ended` and `Failed: 0`), target name via `fno_rename.new_name(path, day, expiries)` (extracted from `plan_root`; expiries from the source root's file), zero-volume setting (name, else `zero_volume_setting`) must match the store, `check_label()`. `compare_live()` / `compare_trees()` compare whole day trees with the live day of the same date. The variant check calls `fno_derive.compare_day(with, without, u, source, name=)` (extracted from `compare_variants`; `derive_day(name=)` lets an old-style with day derive under its new name). The archive step is `fno_clear.plan_clear` + `run_clear(label=, also=, dry_tail=)` with the import's locks already held (`window_lines(also=)` marks lost days that are also in the source); archive `<home>\archive\<YYYY-MM-DD_HHMM IST>_import_<U>`. Apply: `copy_checked()` (copytree to `.part`, `size_of` + SHA-256 of CSVs, rename; `.part` removed on any error), `merge_history()` (`merge_expiries`, `holiday_key`), `write_rows()` (`fno_derive.symbols_of` + `contract_files`; DONE, `ZERO_VOLUME` for listed contracts without a file, chunk_from = WINDOW start like `copy_progress`), `rewrite_counts`, then **the locks are released before publishing** (publish takes each raw root's lock), `publish_variants(..., force=True)` (`publish=` injectable), days.csv printed, `missing_report()` (offline window from the saved expiries, holidays per source, after apply `fno.missing_dates` per store) and `write_report()` (`import_report.txt`, with the undo steps: clear the imported data, then restore, then publish).

## Backtest store
- F&O backtest store (F&O only; each store `D:\Data\fno\raw\{kite,dhan}\<variant>` = ordinary save folders, `backtest\<variant>\<UNDERLYING>\` derived):
  - `backfill/fno_store.py` `move_raw(froms, source, to, apply)` (into a store only days of its setting; CLI `--variant`): day folders of each `fno_root(from, u, source)` go to the same root under `to` (names and bytes unchanged; `same_device()` -> `os.rename`, else `copy_verified()`: copytree to `.part`, sizes checked, rename, then the source removed; a mismatch keeps the source). **Duplicates are never moved, replaced or deleted**: a day the target has in any name form is listed ("incoming has more data" for target noZeroVol vs incoming withZeroVol). `plan()` processes several `--from` in order against a simulated target. Merges: `expiries_seen.csv` union (earliest first_seen, `read_expiries_file`, never seeded from dumps), `holidays.log` lines for holidays not yet listed (`holiday_key()` drops the leading logged-at time), and `INSERT OR IGNORE` of the moved days' `chunks` rows (`run_key(u, day, source)`; source db opened read-only) into `<to>/progress.sqlite`. Locks: every source and target root's `.lock` (a dry run locks only roots that already have one and creates nothing). `--apply` stops on the first error and lists what was moved; the day counts of every touched root (target and old) are rewritten even then. Old roots stay.
  - `backfill/fno_publish.py` `publish(raw, out, underlyings, ...)`: **never writes raw** (it only takes each raw root's `.lock` via `acquire_lock` while reading; busy -> that root skipped, exit 1). Per day and source with summary.csv (else listed as incomplete): `minute/<src>/<YYYY>/<date>.parquet` in `MINUTE_SCHEMA` (`day_frame()`: `fno_loader.read_contract_csv` with `fill_oi`, `bhav.parse_name`, `zero_volume` = the contract's day volume is 0; sorted by contract, datetime; atomic via `write_atomic`). **Incremental:** `publish_manifest.json` holds per day and source the folder and `fingerprint()` (files, bytes, newest mtime of the whole day folder) plus what days.csv needs; a day is rebuilt only when new, changed or `--force`. EOD (`eod/<YYYY>.parquet`, `fno_loader.load_eod` + `EOD_KEYS`) comes from Kite's saved bhavcopy, else Dhan's (`eod_source` in the manifest; the year file is updated per changed day). `contracts.parquet` (`CONTRACT_COLUMNS`; lot from EOD, else the saved instrument lists) and `expiries.csv` (`EXPIRY_COLUMNS`; monthly = last expiry of its month) are rebuilt every run; `days.csv` (`DAYS_COLUMNS`, plus `raw_missing`) from the manifest. **best_source** (`best_source()` -> (source, reason) for days.csv's `best_source` / `best_reason`): rank `CHECK_RANK` OK > minor > unchecked > major (`check_label()` from `bhav.list_days`); the same label is broken by `check_counts()` of bhav_check.json (kept in the manifest entry as `counts`) in `TIE_COUNTS` order, fewer wins: `missing`, then `volume` (`red_volume_diffs`, else `volume_diffs`), then `total` (sum of `bhav.COUNT_NAMES`); only all equal or unknown -> `--prefer` (kite); blank without a source; sources whose raw folder is gone count only when no other is left. A published day whose raw folder is gone is kept and marked until `--prune`.
  - `backfill/fno_backtest.py` reads only the store: `load_fno_day` (`source` best/kite/dhan, `expiry`/`types`/`strikes`/`drop_zero_volume` as pyarrow `filters`, `columns`), `load_fno_range` -> (frame, skipped dates), `load_eod`, `load_days`, `load_contracts`, `load_expiries`; `root` defaults to `config.fno_backtest_dir()`. `fno_loader.py` stays the raw reader.
